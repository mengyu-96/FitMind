## 2. 来源和可信度

原始输入资料为根目录两份txt。2026-09-25用户明确“c01-10全部采取建议方案”，并授权本机Conda环境及要求优化Agent架构，据此建立v1.0计划基线。未开展外部市场调研、法律审查、模型实测或医学验证；方案确认不把这些假设变成事实。

文档采用四种口径：原始要求（源文件明确）、建议方案（本轮细化）、假设（待实验验证）、待确认（需要负责人决定）。无特别声明的技术参数和验收目标均为建议基线，确认后才成为承诺。

## 3. 审批流程

草案 v0.1 → 用户反馈 → 修订草案 → 用户确认范围及版本 → 冻结为 v1.0 → 明确授权开工 → 按里程碑实施。可以只确认部分章节；未确认的关键项保持开放，不默认为接受。

G0 文档批准前不进入编码。G1 原型/技术验证、G2 内测、G3 商业试点、G4 公开上线分别验收。G0 不自动授权付费采购、公开发布或对外宣传；相关预算与上线范围在对应关口明确。

## 4. 冲突和维护

当前M0范围以03及29为准；29将旧完整规格切分为首版与后续，首版自主授权与直接调用同样以29细化。功能操作流程以22/26为准，业务状态/规则/统计以23为准，智能体自由度原则以25 AU为准、主动交流以28 PI为准；接口包络以07、数据约束以06、算法以09、商业数字以14为准，验收映射以11/24/27/28为准。标准表的必填条件只约束相应投影，不得推导成源对象或用户交互的全局限制。冲突须同步修正关联文档，不让开发者自行猜测。源文件不覆盖修改，偏差记录在01和17。

每次修订记录版本、日期、CR、需求及审批依据。C01—C10的v1.0确认保留历史效力；CR-001为Agent优化/环境，CR-002/v1.1为功能细化，CR-003/v1.2为自由度与主动交流，CR-004/v1.3为首版收束，当前CR-005/v1.4为使用中反馈与返回续接。未变材料保留原版本，但不将旧“MVP全部P0”当当前交付清单。Agent结构以19为准，领域评测基线以08为准，具体首版验收以29分期。

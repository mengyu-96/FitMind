## 3. 已随C03确认的差异

| 编号 | 原文 | 本轮建议 | 原因/审批项 |
|---|---|---|---|
| D01 | 服务端轻量、不承载业务 | 服务端领域层负责校验、事务、规则；Agent编排 | 防止模型直接决定权限和资金操作 |
| D02 | 任意数据、任意展示 | 自定义内容保留；渲染组件、动作类型白名单 | 小程序运行边界与注入防护 |
| D03 | thinking为思考过程 | 保留兼容字段但固定null；另用简短决策摘要审计 | 不采集或展示模型内部思维过程 |
| D04 | Redis Pub/Sub作为队列 | PostgreSQL outbox + Redis Streams | 训练事件需要持久化、重试与去重 |
| D05 | 肌肉恢复百分比、过度训练 | 标为模型估算；高疲劳提示不作为医学判断 | 原文未提供验证过的公式 |
| D06 | 原示例疲劳35却为轻度 | 统一阈值；35为估算低疲劳 | 修复示例与阈值矛盾 |
| D07 | 长期记忆永久保存 | 保存期限、可删除、删除后不再检索 | 数据最小化及用户控制 |
| D08 | 康复人群为目标用户 | 首版成年人一般健身；伤病只作限制信息 | 原文同时禁止医疗诊断，需统一边界 |
| D09 | 定时主动联系用户 | 当前改为使用中/返回续接，无离线消息积压；外部事项提醒仅待验证实验 | v1.4/CR-005按用户体验修订，不宣称站内消息必被看到 |
| D10 | 市场空白、竞品功能缺失、必然进步 | 改成待验证主张；用户故事为假设情境 | 当前无市场证据与真实训练结果 |

## 6. v1.2追踪补充

用户明确要求减少固定字段与表单约束，并增强主动提问、反馈及信息获取。25恢复并深化原稿开放资料卡与Agent自主组织的意图：固定执行包络，开放业务payload；26 SC-01—SC-32覆盖跨模块自由路径；27 AF01—AF24验证自由度；28 PI/PQ定义主动交流与验收。F01—F05/F10共同使用柔性内核，F09不再只指离线提醒。范围、权限、来源和医学边界继续有效，具体修订见CR-003。

## 7. v1.3来源与范围修订

用户明确“注意做一定的功能性收束，当前更希望做微信小程序，部分功能是后续才会做的”，同时要求“最大可能开发智能体的主观能动性，赋予更多的权限，允许更自由的调用”。据此29拆分前台核心闭环与后续功能，并增加当前任务/持续自主调整权限、一次调用完成授权内变更的能力族。原始材料不删改，后置功能保留追踪但不占首版关键路径。

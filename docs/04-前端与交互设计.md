# 前端与交互设计

版本：v1.2｜日期：2026-09-25｜状态：开放交互与主动反馈同步

## 1. 信息架构与页面

主入口仍是对话，底部提供“教练 / 训练 / 我的”三个稳定入口；肌肉面板可从教练页卡片或训练页进入。动态内容不能移走设置、返回、数据管理等基本入口。

| 页面 | 主要内容与交互 | 特殊状态 |
|---|---|---|
| 登录/授权 | 微信登录、协议版本、按用途授权 | 拒绝、code过期、重复登录 |
| 教练首页 | 消息流、建议快捷回复、今日训练摘要、输入框 | 新用户引导、生成中、失败重试、离线 |
| 资料抽屉 | 画像/目标/偏好卡片、编辑/归档 | 无卡片、隐藏恢复、版本冲突 |
| 计划详情 | 单次/日期/轮换安排、开放目标、动作、替代、差异与采纳 | 生成失败、局部信息不足、已被替代 |
| 训练执行 | 动作列表、每组重量次数、休息计时、结束 | 暂停、断网、未同步、取消确认 |
| 肌肉面板 | 前后图、图例、更新时间、估算说明 | 数据不足、重算中、数据过期 |
| 肌肉详情 | 历史、指标口径、相关动作、问教练 | 不支持细分、无可比趋势 |
| 动作/设备详情 | 媒体、步骤、常见错误、替代、来源 | 媒体失效、来源撤回、位置缺失 |
| 我的/设置 | 历史、通知、隐私、导出、注销 | 导出排队、重新认证、注销处理中 |
| 内容管理Web | 草稿、审阅差异、发布撤回、反馈队列 | 权限不足、审核驳回；仅内部使用 |

新手首页优先显示学习提示，进阶者优先显示训练变化。排序可以个性化，但相同功能名称和操作位置保持稳定。移动端sidebar映射为抽屉，floating限制为一个可关闭轻提示；不覆盖输入框及训练结束按钮。

## 3. 视觉规范（建议方向）

采用浅色、清晰、克制的教练工具风格。背景#F7F8FA，正文#1F2937，辅助文字#667085，主操作#2457C5；间距4/8/12/16/24/32px，圆角12px，正文16px、说明14px、标题20px。小程序以逻辑尺寸适配，点击区≥44px，适配安全区、系统字体放大与长中文。

热力图颜色沿用原稿灰/绿/黄/橙/红，详细阈值以09为准；不能仅靠颜色传递状态，同时提供文字图例与列表模式。选中描边不改变疲劳数值。蓝色仅用于选择或提示，不再代表医学意义的“过度训练”。文字对比度以WCAG AA作为设计目标，真机复核。

## 4. 动态卡片协议

卡片字段详见07/25。业务type与属性可自定义；display.style为兼容展示提示，支持card/list/table/text/progress/timeline/chart/muscle_heatmap/exercise_detail/equipment_detail/knowledge，并允许用注册组件树自由组合。未知style或业务kind回退安全文本/键值卡。深度4、50个展示字段、单卡32KB为初始渲染预算，可拆卡、折叠、分页或按需读取；不能据此丢弃源业务字段。真正超过请求体安全上限时返回大小限制与分批恢复办法。

location允许main/sidebar/dialog/floating；priority为0—100，数值越高越靠前。MVP支持pinned置顶，先按pinned降序，再priority降序、创建时间升序、ID排序；批量自由重排留P1。用户隐藏/置顶优先于Agent建议。操作只允许预定义action_type和受校验参数；不执行脚本、HTML事件、任意URL或模型提供的SVG路径。

组件：ChatList、ChatBubble、ChatInput、QuickReply、CardRenderer、CardActions、MuscleHeatmap、MuscleLegend、ExerciseDetail、EquipmentDetail、SetInput、RestTimer、SyncBadge、CitationSheet。通用错误边界隔离坏卡片，不能阻断整页。

## 5. 状态与通信

Pinia按auth/chat/cards/training/app拆分；服务端实体按ID规范化缓存，卡片和训练都保存version。前端先显示草稿，服务器回执后才显示“已保存”。训练计时保存开始时刻与暂停累计值，不能依靠后台持续setInterval。

POST消息返回run_id后，WebSocket可订阅运行进度；连接失败以GET轮询补偿。订阅只传短期票据；最后事件序号用于补拉。消息文本增量可丢弃重取最终回复，训练数据以API为准。403不自动无限重试；401最多刷新一次，失败回登录。

缓存建议：公共动作7天带内容版本；用户卡片仅会话缓存；未同步训练草稿保留至同步成功或用户清除。小程序本地存储不视为安全保险箱，避免缓存伤病原文、完整对话和长期凭证。

## 6. 热力图与性能

人体图采用授权且经领域审核的静态路径。统一viewBox坐标到实际显示区域，命中层用经审核多边形或区域表；密集区域提供列表选择，防止点击到相邻肌肉。前后图同一muscle_id共享状态；深层肌肉以列表呈现，不虚构可见解剖位置。

G1验证SVG图片/data URI在目标微信基础库及iOS/Android上的兼容；不通过则采用Canvas或预渲染资产。列表分页50条、窗口化渲染；图表按需加载，避免完整ECharts增加首包。包体以届时平台限制为准并保留20%余量。

## 7. 交付与前端验收

获准开发后交付页面流程、组件库、主题变量、真机适配记录。覆盖小屏/大屏、键盘顶起、前后台切换、弱网、读屏标签、颜色识别障碍。当前为文字与低保真设计，品牌标志、精细人体资产及高保真视觉需G1评审，不宣称已有视觉成品。

## 8. 页面动作与业务反馈（v1.1）

| 页面操作 | 业务命令/规则 | 前端必须展示 |
|---|---|---|
| 首次生成计划 | 当前动作所需证据与用途校验 | 只问影响本次决定的问题，允许先给可支持部分 |
| 采纳/替换计划 | 计划版本+当前active计划ID校验 | 旧新差异、未开始项目变化、进行中训练保留 |
| 开始训练 | 创建实时会话；存在进行中则冲突 | 继续现有训练入口 |
| 单组保存 | entry_id、set_id、expected_version | 次数/计时互斥、实际值与目标分栏、热身标记 |
| 结束训练 | 活动结束与标准会话资格分别校验 | 无组也可保存已结束的自述记录；说明暂不可计算项目，提供可选补充 |
| 取消已录组会话 | 明确放弃或保存部分 | 不以普通返回/关页触发取消 |
| 断网重连 | 重试原操作ID，409展示版本差异 | 未同步数、原值/本地值/服务器值，不能无声覆盖 |
| 修改历史 | 自然语言/局部编辑形成源对象语义修订 | 新版本、实际差异、统计更新中；无须重填完整训练表 |
| 查看旧估算 | projection_status、as_of、coverage | 过期/低覆盖说明，提供有效原始记录入口 |
| 导出/注销 | 再认证和任务状态 | 导出期限、在线阻断/物理清理的区别 |

卡片binding_kind=reference时投影content只读，编辑按钮可以启动自然语言或局部精确编辑，经源对象领域服务提交。身体限制状态条和同步错误条独立于动态卡片显示，不能因隐藏卡片消失。需要确认的动作显示期限与操作目标；已有明确授权范围内的操作直接执行并反馈，不重复弹确认框。过期票据不能静默接受旧计划。

前端流程及异常细节以22/23为准，验收覆盖B01—B28。消息“已送达”、业务“已保存”和派生“更新中”必须有不同文案；run失败也可能已有成功工具，不把整个消息重发作为唯一恢复入口。

## 9. 主动了解用户的会话体验

Agent可在完成当前任务时主动指出观察、给出反馈并提出有价值的问题。例如“这周两次训练都缩短了；如果是时间紧，我可以帮你拆小安排。最近主要是时间不够，还是恢复不过来？”观察必须能追溯到真实记录，解释保持假设语气。问题可自由作答，快捷选项仅为方便，不能限制回答的语义范围。

每条问题可提供“稍后聊 / 不知道 / 不想回答 / 为什么问”轻操作；跳过不阻塞已经可以完成的任务。“少问一点”“今天只记下来”可直接在对话中生效。默认一次0—2问仅为节奏建议，用户主动要求深入讨论时可持续多轮；不显示强制完成度或要求把健康资料填满。

回答不必逐题：一段自然回复可以补足多个议题、纠正旧信息或转移当前目标。用户可查看和修正“教练目前的理解”，区分自述与推测；完整内部议程不强制暴露。问题已在其他页面回答时同步撤下待答提示，已发旧问题标为已更新。

精确表单用于计时/逐组快速记录等明确任务，字段随活动类型与上下文选择；未知值可跳过。开放记录页面展示原始含义、保存状态及可用分析，不能把“尚无A0投影”展示为“保存失败”。新增业务kind用通用组件即可读写，无需先发布专属页面。详细验收见27 AF与28 PQ。

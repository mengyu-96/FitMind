# 前端与交互设计

版本：v1.0｜日期：2026-09-25｜状态：C01—C10建议方案已由用户确认

## 1. 信息架构与页面

主入口仍是对话，底部提供“教练 / 训练 / 我的”三个稳定入口；肌肉面板可从教练页卡片或训练页进入。动态内容不能移走设置、返回、数据管理等基本入口。

| 页面 | 主要内容与交互 | 特殊状态 |
|---|---|---|
| 登录/授权 | 微信登录、协议版本、按用途授权 | 拒绝、code过期、重复登录 |
| 教练首页 | 消息流、建议快捷回复、今日训练摘要、输入框 | 新用户引导、生成中、失败重试、离线 |
| 资料抽屉 | 画像/目标/偏好卡片、编辑/归档 | 无卡片、隐藏恢复、版本冲突 |
| 计划详情 | 周安排、动作、替代、差异确认、采纳 | 生成失败、信息不足、已被替代 |
| 训练执行 | 动作列表、每组重量次数、休息计时、结束 | 暂停、断网、未同步、取消确认 |
| 肌肉面板 | 前后图、图例、更新时间、估算说明 | 数据不足、重算中、数据过期 |
| 肌肉详情 | 历史、指标口径、相关动作、问教练 | 不支持细分、无可比趋势 |
| 动作/设备详情 | 媒体、步骤、常见错误、替代、来源 | 媒体失效、来源撤回、位置缺失 |
| 我的/设置 | 历史、通知、隐私、导出、注销 | 导出排队、重新认证、注销处理中 |
| 内容管理Web | 草稿、审阅差异、发布撤回、反馈队列 | 权限不足、审核驳回；仅内部使用 |

新手首页优先显示学习提示，进阶者优先显示训练变化。排序可以个性化，但相同功能名称和操作位置保持稳定。移动端sidebar映射为抽屉，floating限制为一个可关闭轻提示；不覆盖输入框及训练结束按钮。

## 3. 视觉规范（建议方向）

采用浅色、清晰、克制的教练工具风格。背景#F7F8FA，正文#1F2937，辅助文字#667085，主操作#2457C5；间距4/8/12/16/24/32px，圆角12px，正文16px、说明14px、标题20px。小程序以逻辑尺寸适配，点击区≥44px，适配安全区、系统字体放大与长中文。

热力图颜色沿用原稿灰/绿/黄/橙/红，详细阈值以09为准；不能仅靠颜色传递状态，同时提供文字图例与列表模式。选中描边不改变疲劳数值。蓝色仅用于选择或提示，不再代表医学意义的“过度训练”。文字对比度以WCAG AA作为设计目标，真机复核。

## 4. 动态卡片协议

卡片字段详见07。业务type可自定义；display.style仅允许card/list/table/text/progress/timeline/chart/muscle_heatmap/exercise_detail/equipment_detail/knowledge。未知style回退安全键值卡；复杂嵌套按最大深度4、最大50字段、正文折叠处理。单卡JSON建议≤32KB，超过返回校验错误。

location允许main/sidebar/dialog/floating；priority为0—100，数值越高越靠前，同优先级按创建时间升序。用户固定排序优先于Agent建议。操作只允许预定义action_type和受校验参数；不执行脚本、HTML事件、任意URL或模型提供的SVG路径。

组件：ChatList、ChatBubble、ChatInput、QuickReply、CardRenderer、CardActions、MuscleHeatmap、MuscleLegend、ExerciseDetail、EquipmentDetail、SetInput、RestTimer、SyncBadge、CitationSheet。通用错误边界隔离坏卡片，不能阻断整页。

## 5. 状态与通信

Pinia按auth/chat/cards/training/app拆分；服务端实体按ID规范化缓存，卡片和训练都保存version。前端先显示草稿，服务器回执后才显示“已保存”。训练计时保存开始时刻与暂停累计值，不能依靠后台持续setInterval。

POST消息返回run_id后，WebSocket可订阅运行进度；连接失败以GET轮询补偿。订阅只传短期票据；最后事件序号用于补拉。消息文本增量可丢弃重取最终回复，训练数据以API为准。403不自动无限重试；401最多刷新一次，失败回登录。

缓存建议：公共动作7天带内容版本；用户卡片仅会话缓存；未同步训练草稿保留至同步成功或用户清除。小程序本地存储不视为安全保险箱，避免缓存伤病原文、完整对话和长期凭证。

## 6. 热力图与性能

人体图采用授权且经领域审核的静态路径。统一viewBox坐标到实际显示区域，命中层用经审核多边形或区域表；密集区域提供列表选择，防止点击到相邻肌肉。前后图同一muscle_id共享状态；深层肌肉以列表呈现，不虚构可见解剖位置。

G1验证SVG图片/data URI在目标微信基础库及iOS/Android上的兼容；不通过则采用Canvas或预渲染资产。列表分页50条、窗口化渲染；图表按需加载，避免完整ECharts增加首包。包体以届时平台限制为准并保留20%余量。

## 7. 交付与前端验收

获准开发后交付页面流程、组件库、主题变量、真机适配记录。覆盖小屏/大屏、键盘顶起、前后台切换、弱网、读屏标签、颜色识别障碍。当前为文字与低保真设计，品牌标志、精细人体资产及高保真视觉需G1评审，不宣称已有视觉成品。

# 后端详细设计

版本：v1.1｜日期：2026-09-25｜状态：功能业务细化同步

## 1. 模块与依赖

| 模块 | 责任 | 禁止跨越的边界 |
|---|---|---|
| auth/users | 微信登录、会话、授权、注销 | 模型不能设置身份与角色 |
| conversations | 消息、运行、结果投递 | 不以回复文本判断事务成功 |
| agent | 上下文、工具规划、模型适配 | 不直接写SQL、不绕过领域规则 |
| cards/profiles | JSONB卡片、类型、历史、画像确认 | 展示卡不能作为训练事实来源 |
| plans | 草稿、校验、采纳、版本 | 激活计划需用户明确采纳 |
| training | 会话、逐组记录、完成、修订 | 同一完成指令不可重复记账 |
| muscles | 可重建的肌肉状态投影 | 不覆盖原始训练事实 |
| knowledge | 入库审核、检索、引用 | 公共知识不含个人记忆 |
| scheduler | 到期扫描、站内信、通知投递 | 未授权/静默不得外部触达 |
| governance | 导出、删除、审计、反馈 | 不记录令牌与完整敏感提示词 |

建议目录app/api、domain、repositories、agent、workers、schemas、adapters、observability。依赖顺序API→领域服务→仓储/适配器，HTTP与Agent工具复用领域服务。

## 2. 身份和授权

小程序提交临时code，后端与微信服务交换标识；应用建立自己的用户ID和会话，不将session_key返回客户端。建议访问令牌30分钟，刷新令牌7天轮换，数据库保存刷新令牌哈希及撤销状态。最终时长需安全评审。

所有私有查询显式包含user_id，由认证上下文赋值。管理权限细分editor/reviewer/admin，内容审核员不具有个人训练读取权。用户资源跨账号访问返回404；管理员接口记录操作者、用途和变更结果。

## 3. 事务与幂等

修改请求携带Idempotency-Key，键按user_id+路由+键作用域唯一，保存请求哈希和首次响应至少24小时；相同键不同请求体返回409。训练完成另有会话状态与唯一业务约束，超过24小时重试也不会重复产生事实。

完成训练事务：锁定用户事实revision与会话 → 校验状态/版本/有效组 → 写入completed及版本 → 递增用户training_revision并更新计划履约 → 创建领域事件和outbox → 提交。同一幂等请求返回原结果；新键请求已经completed的会话返回409 ALREADY_COMPLETED及原完成引用，后续修改引导修订接口。卡片及计划使用version条件更新，失败返回409和最新版本，不静默覆盖。

计划采纳在用户级锁内校验expected_active_plan_id及草稿输入版本，将原active变superseded并激活新版本。更新未开始的计划项，保留进行中会话快照；数据库部分唯一索引提供第二层保护。外部模型调用不放入数据库长事务；模型超时不会持有业务锁。

## 4. 异步与一致性

outbox发布器把已提交事件投递Redis Streams；消费者用consumer_name+event_id去重。消费后记录成功再ACK；宕机未ACK可重领。发布成功但未标记造成重复，由消费者去重解决。不宣称消息系统提供exactly-once。

建议重试1/5/30/120/600秒，5次失败进入死信并告警。肌肉投影采用user_id串行或版本CAS；写入source_revision，老任务不能覆盖新版本。重算任务读取用户全部有效训练事实或版本化检查点，不把每次事件简单累加。

Redis不可用时outbox积压，核心训练仍能提交。恢复后补发；UI显示“训练已保存，状态更新中”。定时对账扫描已完成训练与投影revision差异。

## 5. Agent运行与配额

run状态queued/running/awaiting_confirmation/succeeded/failed/cancelled；累计执行最长60秒，等待确认不计入，票据默认30分钟过期。采用LangGraph主教练与专项子图，每run最多4次模型调用、6次工具、2轮检索和24个图步骤；修复重试同样占用预算，详见19。

每用户同一时刻最多一个正在执行副作用的run，用数据库租约和fencing_token阻止旧worker写入。awaiting_confirmation释放租约，新消息可处理，恢复时检查授权和资源版本。PostgreSQL检查点用于恢复流程，tool_executions与业务事实同事务提交，消除业务提交后检查点尚未保存时的重复写入风险。

为模型、检索、媒体接口分别设置超时和熔断。失败后保留用户消息与可恢复运行状态；不自动重放未经幂等保护的工具。记录token量、估算费用、供应商错误码与trace_id；配额到达后保留非AI核心功能。

## 6. 调度

每分钟扫描next_due_at，使用租约抢占任务。提醒候选唯一键user_id+kind+source_id+window_key，延期不改变去重键；每日最多1条主动提醒、相邻投递至少20小时，默认22:00—08:00静默。频控名额与站内消息在同一用户锁事务内提交，细节按23 BR-13。提醒到期再次核对训练是否已完成，避免过时催促。

默认仅站内；微信订阅消息必须在平台规则、模板与用户授权允许时发送。票据耗尽/拒绝不循环请求，不伪装推送成功。健康细节不写入锁屏通知。

## 7. 后续计费边界

MVP可记录功能使用量但不接收真实支付。V1支付须增加订单/支付流水/权益账本，验签、金额币种校验、通知去重、退款逆向权益和每日对账。前端支付成功提示不能直接开通权益。

## 8. 领域命令与业务不变量（v1.1）

完整规则见23 BR-01—BR-16；HTTP和Agent共用下列领域入口，不能维护两套“聊天特例”。

| 命令 | 事务不变量 | 事件与后续 |
|---|---|---|
| ConfirmProfile | 字段来源、用途、expected_version；资格变化即时阻断不兼容计划 | profile.updated，失效旧确认与记忆 |
| AcceptPlan | 当前active CAS、草稿/画像/训练/内容版本、发布状态 | plan.accepted；未来提醒更新 |
| StartSession | 单用户至多一个实时in_progress/paused，计划项有效 | 固化快照，创建条目，尚无完成训练事件 |
| UpsertSet | entry归属、计量互斥、实际值、会话未结束 | 会话version递增；未完成事实不进肌肉计算 |
| CompleteSession | 至少一个完成组；统计类型与目标映射正确 | training.completed带training_revision |
| RecordRetroactive | 日期精度、单位、重复提示已解决，完整事实同事务 | 直接completed，不占实时训练名额 |
| ReviseSession | 既有ID归属、新ID唯一、完整快照、不留零有效组 | training.revised；派生与报告失效 |
| DeleteSession | deleted_at即时屏蔽、用户revision递增、关联履约更新 | training.deleted；物理清理/重算 |
| UpdateCard | reference内容不能直写；显示偏好独立 | card.updated，不修改源训练 |
| WithdrawContent | 同步写撤回状态和资格阻断依据 | knowledge.withdrawn/content.withdrawn；异步清理不阻塞撤回生效 |

锁顺序统一为用户事实/计划范围→会话或计划项→子条目→派生引用，避免不同工具相反顺序造成死锁。训练写入未完成组只增session.version，完成/修订/删除才递增用户training_revision。响应明确事实保存状态和投影状态。

## 9. 读模型与后台业务任务

GET训练/计划详情必须可以按ID重建页面，不能只靠对话缓存。历史查询默认排除cancelled/deleted，按业务发生时间游标排序，后台统计显式区分提交时间与发生时间。肌肉读取使用用户revision和统一as_of，最长5分钟缓存；无新事实也按时刻衰减，返回coverage及过期原因。

按需复盘保存source_revision、计划快照和规则版本；源变化后读路径标stale，异步重算不能覆写原报告历史。提醒候选先按BR-13判断，再生成一条站内消息；外部通道另有授权/平台校验。导出快照和注销任务按BR-16隔离，注销回执不复用普通登录令牌。

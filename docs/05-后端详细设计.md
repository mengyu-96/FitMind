# 后端详细设计

版本：v1.4｜日期：2026-09-25｜状态：柔性业务内核与主动信息获取同步

> v1.3实施范围：M0按29建设认证、源对象、统一变更、基本计划、知识及数据治理；实时训练命令、肌肉、离线提醒与报告任务中心为后续设计。 具体分期与自主授权以[29](29-微信小程序首版收束与智能体授权.md)为准。

## 1. 模块与依赖

| 模块 | 责任 | 禁止跨越的边界 |
|---|---|---|
| auth/users | 微信登录、会话、授权、注销 | 模型不能设置身份与角色 |
| conversations | 消息、运行、结果投递 | 不以回复文本判断事务成功 |
| agent | 上下文、工具规划、模型适配 | 不直接写SQL、不绕过领域规则 |
| cards/profiles | JSONB卡片、类型、历史、画像确认 | 展示卡不能作为训练事实来源 |
| objects/changes | 柔性事实、证据、语义修改、版本及投影绑定 | 所有业务写入回到同一事实源，不由模型指定归属 |
| inquiry/mandates | 关注议程、回答吸收、用户授权范围及撤销 | 议题不能变成必填清单；提问权限不等于执行授权 |
| plans | 草稿、校验、采纳、版本 | 激活需用户明确意图或覆盖实际效果的有效委托 |
| training | 会话、逐组记录、完成、修订 | 同一完成指令不可重复记账 |
| muscles | 可重建的肌肉状态投影 | 不覆盖原始训练事实 |
| knowledge | 入库审核、检索、引用 | 公共知识不含个人记忆 |
| engagement | 前台议程筛选、返回候选与呈现去重 | 不扫描离线用户生成消息；外部通知另作待验证实验 |
| governance | 导出、删除、审计、反馈 | 不记录令牌与完整敏感提示词 |

建议目录app/api、domain、repositories、agent、workers、schemas、adapters、observability。依赖顺序API→领域服务→仓储/适配器，HTTP与Agent工具复用领域服务。

## 2. 身份和授权

小程序提交临时code，后端与微信服务交换标识；应用建立自己的用户ID和会话，不将session_key返回客户端。建议访问令牌30分钟，刷新令牌7天轮换，数据库保存刷新令牌哈希及撤销状态。最终时长需安全评审。

所有私有查询显式包含user_id，由认证上下文赋值。管理权限细分editor/reviewer/admin，内容审核员不具有个人训练读取权。用户资源跨账号访问返回404；管理员接口记录操作者、用途和变更结果。

## 3. 事务与幂等

修改请求携带Idempotency-Key，键按user_id+路由+键作用域唯一，保存请求哈希和首次响应至少24小时；相同键不同请求体返回409。训练完成另有会话状态与唯一业务约束，超过24小时重试也不会重复产生事实。

标准会话完成事务：锁定用户事实revision与源活动/会话 → 校验授权、状态、版本及投影有效组 → 写入源活动修订与completed投影 → 递增一次用户training_revision并更新计划履约 → 创建领域事件和outbox → 提交。同一幂等请求返回原结果；新键请求已经completed的会话返回409 ALREADY_COMPLETED及原完成引用，后续修改引导修订接口。开放活动无有效组也可保存为finished，不冒充标准会话完成。卡片及计划使用version条件更新；不相交语义补丁可按授权合并，同字段冲突返回差异。

计划采纳在用户级锁内校验expected_active_plan_id及草稿输入版本，将原active变superseded并激活新版本。更新未开始的计划项，保留进行中会话快照；数据库部分唯一索引提供第二层保护。外部模型调用不放入数据库长事务；模型超时不会持有业务锁。

## 4. 异步与一致性

outbox发布器把已提交事件投递Redis Streams；消费者用consumer_name+event_id去重。消费后记录成功再ACK；宕机未ACK可重领。发布成功但未标记造成重复，由消费者去重解决。不宣称消息系统提供exactly-once。

建议重试1/5/30/120/600秒，5次失败进入死信并告警。肌肉投影采用user_id串行或版本CAS；写入source_revision，老任务不能覆盖新版本。重算任务读取用户全部有效训练事实或版本化检查点，不把每次事件简单累加。

Redis不可用时outbox积压，核心训练仍能提交。恢复后补发；UI显示“训练已保存，状态更新中”。定时对账扫描已完成训练与投影revision差异。

## 5. Agent运行与配额

run状态queued/running/awaiting_confirmation/succeeded/failed/cancelled；确认票据默认30分钟过期。采用LangGraph主规划器与可组合能力模板；quick/standard/deep预算由服务端按任务分配。4次模型调用、6次工具、2轮检索、24个图步骤和累计执行60秒为standard初始配置，等待用户不计执行时间。预算在task_id范围跨run、修复和子任务累计，不因恢复而重置；deep仍有明确上限，详见19/25。

每用户同一时刻最多一个正在执行副作用的run，用数据库租约和fencing_token阻止旧worker写入。awaiting_confirmation释放租约，新消息可处理，恢复时检查授权和资源版本。PostgreSQL检查点用于恢复流程，tool_executions与业务事实同事务提交，消除业务提交后检查点尚未保存时的重复写入风险。

为模型、检索、媒体接口分别设置超时和熔断。失败后保留用户消息与可恢复运行状态；不自动重放未经幂等保护的工具。记录token量、估算费用、供应商错误码与trace_id；配额到达后保留非AI核心功能。

## 6. 前台续接与必要后台任务

首版不运行离线教练提醒调度器；next_review_at到期只改变下一次交互的候选资格，禁止每分钟扫描后生成inbox。后台只恢复已受理任务及处理索引、导出、删除等必要业务，恢复已提交回执不算新的主动目标。

用户进入教练页时先完成轻量资格筛选与visit/主题去重，再按任务预算生成可忽略候选；无候选立即返回none。前端核心页面不等待模型。候选发布时查最新议题、答案、偏好和交互代次，旧run结果不得覆盖用户的新请求。展示占位/engagement键采用用户级事务约束，多端重试返回同一决定或none。

候选不预写assistant消息，客户端呈现回执只证明展示；缺回执记未知，不以重试补弹。当前外部通知关闭，未来用户指定事项的订阅实验另行设计和核验平台能力，不能复用旧每日推送初值。

## 7. 后续计费边界

MVP可记录功能使用量但不接收真实支付。V1支付须增加订单/支付流水/权益账本，验签、金额币种校验、通知去重、退款逆向权益和每日对账。前端支付成功提示不能直接开通权益。

## 8. 领域命令与业务不变量（v1.1）

完整规则见23 BR-01—BR-16；HTTP和Agent共用下列领域入口，不能维护两套“聊天特例”。

| 命令 | 事务不变量 | 事件与后续 |
|---|---|---|
| ConfirmProfile | 字段来源、用途、expected_version；资格变化即时阻断不兼容计划 | profile.updated，失效旧确认与记忆 |
| AcceptPlan | 当前active CAS、草稿/画像/训练/内容版本、发布状态 | plan.accepted；相关关注议程按需更新，不自动建通知 |
| StartSession | 单用户至多一个实时in_progress/paused，计划项有效 | 固化快照，创建条目，尚无完成训练事件 |
| UpsertSet | entry归属、计量互斥、实际值、会话未结束 | 会话version递增；未完成事实不进肌肉计算 |
| CompleteSession | 至少一个完成组；统计类型与目标映射正确 | training.completed带training_revision |
| RecordRetroactive | 日期精度、单位、重复提示已解决，完整事实同事务 | 直接completed，不占实时训练名额 |
| ReviseSession | 既有ID归属、新ID唯一，服务端由语义补丁构造修订；零有效组时撤销标准投影资格 | 源活动保留，training.revised；派生与报告失效 |
| DeleteSession | deleted_at即时屏蔽、用户revision递增、关联履约更新 | training.deleted；物理清理/重算 |
| UpdateCard | reference内容不能直写；显示偏好独立 | card.updated，不修改源训练 |
| WithdrawContent | 同步写撤回状态和资格阻断依据 | knowledge.withdrawn/content.withdrawn；异步清理不阻塞撤回生效 |

锁顺序统一为用户事实/计划范围→源活动、会话或计划项→子条目→派生引用，避免不同工具相反顺序造成死锁。源活动每次实际修订递增一次training_revision；投影重建不重复递增，未完成组按资格不进负荷计算。其他个人上下文使用context_revision。响应明确事实保存状态和各消费者投影状态。

## 9. 读模型与后台业务任务

GET训练/计划详情必须可以按ID重建页面，不能只靠对话缓存。历史查询默认排除cancelled/deleted，按业务发生时间游标排序，后台统计显式区分提交时间与发生时间。肌肉读取使用用户revision和统一as_of，最长5分钟缓存；无新事实也按时刻衰减，返回coverage及过期原因。

按需复盘保存source_revision、计划快照和规则版本；源变化后读路径标stale，异步重算不能覆写原报告历史。前台关注候选按BR-13评估，未展示不生成对话或站内信；外部通道当前不启用。导出快照和注销任务按BR-16隔离，注销回执不复用普通登录令牌。

## 10. 开放能力与主动对话的领域入口

`RecordObservation`接受未知业务kind、部分payload及可追溯来源，校验最小包络和用途后即保存；消费者各自报告eligible/partial/ineligible及理由。`ProposeChanges → ValidateChanges → CommitChanges`共享同一领域事务：检验源版本、真实效果、授权/委托范围和当前政策，原子落库修订、即时执行投影、委托用量、稳定operation回执与outbox。验证票据不是授权，模型提出的风险等级不作为服务端决策依据。

`OpenInquiry / GiveFeedback / AbsorbAnswer / DeferInquiry`支持自主选择话题和措辞。回答可关联多个议题，也可新建先前未设字段；只写用户确实表达的内容，拒答不是阴性结论，转移话题不是默认同意。引用必须属于本人可用来源。议题状态、源事实、回答版本和待发候选的失效在同一事务处理；相同答案重放不得重复建事实。

主动对话先响应用户当前诉求，再选择是否反馈、问一个关键问题或暂不打扰；没有未填字段也可根据变化提出问题，有未填字段也可不问。用户返回时先做轻量相关性筛选，有明确价值才调用模型；不扫描离线用户生成关注消息。任务失败保留已成功回执与议题进展，不把提问失败回滚成记录失败。

## 11. M0最小实现与直接执行

向Agent提供29中的能力族。apply_changes复用已有提议/验证/提交职责，在一次调用内部完成版本、来源、效果与授权校验；授权足够则执行，缺新授权才返回确认票据。普通已授权写入不必先创建独立change_set资源，也不必强制模型走三轮工具。

用户的明确任务、前台有效持续委托都可覆盖复合动作；服务端事务核验实际效果与范围，范围内不要求固定按按钮采纳。持续委托可保存跨会话权限，M0执行仅由用户消息/打开小程序触发，后台worker只做已受理任务恢复及索引、导出、删除等必要处理，不主动扩展目标。

首版内部审核可通过受限接口/导入工具完成，后台权限和版本审计仍需实现；不以完整运营Web为前置依赖。

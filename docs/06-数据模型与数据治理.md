# 数据模型与数据治理

版本：v1.2｜日期：2026-09-25｜状态：柔性事实与主动信息获取设计；尚未生成数据库迁移

## 1. 通用约定

业务ID用UUID，字典ID用稳定字符串；时间用timestamptz存UTC，显示按用户时区，默认Asia/Shanghai。实体created_at/updated_at必填，可变实体含version正整数。小数用numeric，未知使用null，不用0冒充未知。

个人业务事实统一存入fitness_objects及不可变修订，内容使用柔性JSONB；归属、版本、授权、生命周期和引用使用关系约束。profiles/plans/training等表为执行与查询投影，不构成第二份事实权威，也不要求用户提交对应完整表单。用户只保存一份逻辑隔离的训练库，不为每个用户创建物理数据库。所有用户子实体user_id外键必填，并在关联对象时验证同属一人。

## 4. 事实、投影与版本

fitness_objects保存用户自述、明确执行记录和可追溯的推断，claims区分其证据性质；用户自述不等于已独立核实。结构化训练、画像、计划、卡片、肌肉状态、周报与向量记忆由同一源对象派生。删除展示卡不等于删除源事实。用户要求删除某条训练时，标记源事实失效并重算相关投影；注销时清除全部个人事实与派生数据。手工精确编辑与Agent语义修改必须通过同一领域服务修改源对象，再更新投影，禁止直接写投影后反向猜测源对象。

embedding维度由所选模型确定，不能机械沿用原文1024。迁移模型时建立新版本索引、批量重嵌入、离线验证、切读流量、再清旧索引；禁止混合不同向量空间。JSONB schema升级提供迁移器和回退策略，不修改历史快照。

## 5. 数据保留建议

| 数据 | 建议期限 | 删除行为 |
|---|---|---|
| 画像/训练/卡片 | 账户有效期间，年度提示管理 | 用户删除立即从在线查询排除，30天内完成物理清除 |
| 原始对话 | 默认180天 | 到期清除；来源摘要按必要性重审 |
| 短期缓存 | 最长24小时 | 注销/撤权主动失效 |
| Agent检查点与确认票据 | 终态后建议7天清理；待确认最长30分钟 | 归属用户注销后在线立即拒读，按30天物理清除窗口删除；仅保留必要脱敏审计 |
| 脱敏技术日志 | 30天 | 自动轮转，无对话全文 |
| 管理审计 | 建议180天 | 法定义务另核定，隔离最小必要字段 |
| 备份 | 滚动30天 | 到期淘汰；恢复前重放删除清单 |
| 导出文件 | 24小时 | 下载链接15分钟有效，可重新签发 |

以上为产品设计建议，正式期限需主体和法务核定。法律要求保留的数据说明类别、依据、截止时间，不能以“审计”名义永久保留健康原文。

## 6. 数据质量

单位统一kg、cm、秒；原始输入单位及转换方式可追溯。字段设合理上限并对极端值二次确认，不能武断修改真实记录。每日检查孤儿引用、重复事实、非法状态、过期知识、投影revision落后；修复走可审计任务。

## 7. 业务约束补充（v1.1）

time_precision=exact要求started_at/ended_at在完成时有效；date只要求local_date/timezone且真实时刻可空。derived_effective_at仅用于算法，不冒充事实；按23 BR-08生成。未知重量不是0，bodyweight的null与外部负重0有不同含义。measurement_type和动作允许的计量类型必须匹配。

每occurrence最多一个未删除completed会话；存在有效completed会话时不再允许实时会话绑定；没有completed时最多一个进行中实时会话。补录绑定时拒绝已被进行中会话占用的occurrence，防止补录完成后现有会话也提交完成。数据库唯一约束与事务校验并用。修订中现有entry/set ID必须属于当前用户和会话，新ID不得跨会话复用；物理外键按(user_id,id)组合约束避免只验证父ID。

标准training_sessions投影的completed至少1个有效组；源活动可以finished且没有可计算组。修订移除全部有效组时保留真实活动，撤销其标准完成投影资格并重算，不能要求用户删除整条活动。reference卡不复制源对象作为第二事实，删除源对象后不能继续从card_versions对普通用户展示源敏感快照。用户training_revision与会话version各司其职。

动作与器械已有status/version，在实际DDL中需增加不可变内容版本、submission/review记录及published_version指针，复用知识发布流程；不能只给知识文章建审核表。反馈处理含resolution_code、user_visible_reply、reviewer_id、resolved_at，内部备注与对用户回复分开。

## 8. 柔性事实、授权与关注议程（v1.2）

| 实体 | 最小可信字段与可扩展内容 | 必须保持的不变量 |
|---|---|---|
| fitness_objects | id,user_id,kind,payload,lifecycle,version,purpose_keys；schema_ref可选 | kind和业务属性开放；归属/用途/版本由服务端控制；源活动ID稳定 |
| object_revisions | object_id,user_id,version,snapshot,actor,evidence_refs,operation_id | 对象+版本唯一；历史不可原地覆盖，删除策略仍适用 |
| claim_evidence / object_relations | 声明及字段路径、source_ref、evidence_kind、uncertainty、有效期；关系两端引用 | claim为语义声明，统一证据表名claim_evidence；自述/推断/未知/拒答可区分；关联同属一人或合法公共资源；模型不能自授verified |
| personal_schemas / semantic_maps | 本人类型、可选属性说明、单位/别名/量表定义、版本 | 不要求每类记录先建schema；映射未经确认不能改变原意；不能改系统权限字段 |
| projection_bindings | object_id,consumer,projection_key,source_version,projection_version,status,reasons | 对象+消费者+投影键唯一；拆成多个entry也不得创建多场活动 |
| mandates / mandate_usage | 用户授权证据、scope、actions、effect_limits、expiry、usage、status、version | 服务端匹配实际效果；提交事务内检查并扣用；撤销后新提交失败 |
| change_sets / operations | task_id,operation_id,semantic_patch,base_versions,effect_summary,authorization_ref,status,result_ref | operation_id按用户全局唯一并绑定意图与参数；跨run重试返回原回执，不重复写事实 |
| validation_receipts | change_set_id,content_hash,resource_versions,policy_version,expiry | 校验结果绑定内容与版本；不是授权凭据，提交仍校验当前授权 |
| inquiry_agendas / inquiry_answers | 固定归属、来源、用途、状态、版本；topic/decision_impact等放可扩展payload，next_review_at可空；回答来源及answer_revision | 源关注对象的执行索引；不存隐藏思维过程，回答可解决多议题；拒答/延期可撤销；不为凑字段建议题 |
| interaction_preferences | 主动程度、回复节奏、免问主题、范围和有效期、version | 会话与离线通知偏好分开；用户指令优先，明确例外不能扩大为全局授权 |
| task_budgets | task_id,parent_task_id,profile,limits,reserved,consumed,policy_version | 同一任务跨run/恢复/子任务累计；模型不能自行提额 |

源活动的activity_status（reported/ongoing/finished/unknown）、对象lifecycle与各消费者projection_status独立。“今天练腿，很累”可正式保存并结束，时间、动作、组数未知不伪造；range/unknown时间保留范围。标准表的exact/date、整数RPE等约束只限制该投影；源层可保存区间、自定义量表和自然语言。

training_revision在每次改变训练源活动的事务中递增一次；非训练个人上下文使用context_revision。逐组编辑源活动也遵守此规则，计算器按资格过滤，不能仅因revision增加便把进行中训练算作完成。纯投影重建只增projection_version，不再制造事实变化；tool_executions仍记录run/tool调用，但所有副作用必须引用稳定operation_id与最终回执。

即时可计算的执行投影与源修订同事务落库；昂贵派生通过outbox更新。不可暂时保留失效的执行资格，异步重算期间旧结果标stale。收到回答后原子写入源事实/答案、递增answer_revision、更新议题并取消相关待发候选；提醒提交前重查inquiry_version/answer_revision。外部通道发送前再次校验，已经发出的消息不能保证撤回，竞态处理见28。

导出/删除沿object→revision/claim/relation/schema/map→projection/view/memory→agenda/mandate/operation逐层覆盖。原始对话片段不因被复制到agenda或审计而永久保留；来源到期后重审必要摘要的依据及期限。

执行投影统一增加source_object_id、source_version、adapter_version、validity（eligible/ineligible）和ineligible_reasons，组合外键验证归属。会话曾completed后被纠正为无有效组时，保留历史生命周期但当前validity=ineligible；completed唯一性约束、履约与算法只看未删且eligible的投影。补齐后在同一绑定重新取得资格，不重新创建活动。用户表增加context_revision；inquiry_agendas主键统一称inquiry_id（28中的agenda_id为概念别名），其余议题接口统一使用inquiry_id。

owned卡创建时先建对应源对象并返回source_ref，删除owned卡只移除视图，源内容仍可从个人信息/记录入口管理；删除源内容另走明确删除命令。reference与owned均不能把缓存内容当第二份事实。

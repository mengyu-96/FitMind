# 安全隐私与合规方案

版本：v1.2｜日期：2026-09-25｜状态：柔性信息与主动交流用途同步；正式上线需按主体、地区、服务内容复核

## 1. 数据分类与用户控制

账号标识为个人信息；身体指标、伤病自述、训练与健康相关推断按敏感信息强保护设计。收集前说明目的、必要性、处理方式、期限、供应商类别和撤回入口；敏感处理设置单独明确授权，不与基础浏览捆绑。

首次授权、通知授权、外部模型处理告知分别管理，记录政策版本。拒绝非必要收集可使用通用内容；撤回后停止相关个性化处理及提醒。默认不启用个人对话作为模型训练数据，供应商是否允许关闭保留或训练用途须合同核实。

功能用途键与可用性以23 BR-01为准，personal_training、health_profile、ai_coaching、proactive_reminders分别授权。撤回不自动等于删除，提供单独清理入口；注销则立即阻断访问。导出需要绑定用途的再认证，注销后不保留普通登录态供轮询，仅允许不含个人内容的最小回执查询（BR-16）。

## 2. 权限与威胁控制

| 威胁 | 控制 | 验证 |
|---|---|---|
| 改ID读取他人资料 | 用户过滤、对象归属复核、最小权限 | 两账号遍历所有私有接口 |
| 文档或对话注入工具指令 | 工具白名单、参数schema、用户绑定 | 恶意知识片段/越权测试 |
| 动态卡片脚本/恶意链接 | 文本转义、URL白名单、固定渲染器 | XSS及未知组件样例 |
| 训练重放/支付伪造 | 幂等、状态约束、后续支付验签 | 重复与乱序请求 |
| 密钥泄露 | 密钥管理、客户端无供应商密钥、日志脱敏 | 仓库与构建产物扫描 |
| 管理员滥用 | 角色分离、内容操作留痕、紧急访问审批 | 审核人员不能读私有对话 |
| 批量滥用/费用攻击 | 用户/IP限流、token预算、熔断 | 429与配额降级测试 |
| 删除后在向量/备份复现 | 来源失效、级联清理、恢复重放删除清单 | 全链路注销及备份演练 |

传输TLS；数据库和对象存储启用静态加密，备份分权加密。高敏字段是否额外字段级加密需结合检索需求评估，不宣称已有端到端加密。

## 3. 健康建议边界

产品提供一般健身信息与记录，不诊断疾病、不开药、不承诺康复疗效。胸痛、昏厥、明显呼吸困难等危险描述优先提示停止训练并及时寻求当地紧急医疗帮助；普通疼痛也不能仅凭热力图建议继续。

首版建议面向18岁及以上用户，不做儿童、孕产康复或疾病治疗计划。此范围为待确认商业取舍，不能用免责声明替代系统限制、内容审阅和测试。

## 5. 必备用户文本清单

上线需完成《用户协议》《隐私政策》《敏感个人信息处理告知与同意》《AI建议与估算指标说明》《通知偏好说明》《数据导出与注销说明》，V1另加《会员与退款规则》。当前缺公司主体、联系邮箱、供应商、部署区域，不能以占位文本作为正式法律文件发布。

核心告知草案：“FitMind依据你提供的训练记录生成健身建议。肌肉图为估算结果，不代表真实生理测量或医疗诊断。你可以在设置中管理授权、导出或删除个人数据。”正式文本须补全主体、权利行使渠道和适用范围。

## 6. 事件处置

发现疑似泄露或有害建议 → 限制受影响功能和密钥 → 保留最小必要审计证据 → 确定影响用户与数据 → 修复验证 → 按实际法定义务及平台规则通知 → 复盘更新测试集。建议P0事件15分钟内响应，由值班负责人统一指挥；未配置值班团队前不承诺全天人工响应。

## 7. 开放字段与主动提问的用途管理

字段可自由定义不代表数据可自由用于任何目的。服务端依据内容、来源、业务上下文和实际动作分类purpose_keys；Agent的kind、标签或risk声明不能降低保护等级。未能可靠分类的个人payload按较严格个人信息规则隔离，使用前检查授权；拒绝相应用途时不把敏感正文悄悄存入笔记、agenda或日志绕过。

会话中相关追问使用既有AI及对应数据用途授权，无须为每个问题再申请提问许可；离线主动联系另查proactive_reminders和渠道权限。议题必须有服务目的与来源，不因“将来可能有用”收集无关隐私。免问主题记录最小范围与期限，拒答不推断用户的健康状态；用户可查看、纠正、延期或清理这些信息。

导出与删除包括fitness_objects、修订、claim_evidence、关系、个人schema、语义映射、视图、关注议程与答案、交互偏好、委托、关联检查点及向量。证据链接遵守来源保留期限，必要摘要另有用途和期限，不能无限复制原文规避对话清理。明确删除的信息不能通过旧卡片、计划快照、后台任务或模型上下文重新恢复。

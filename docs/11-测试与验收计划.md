# 测试与验收计划

版本：v1.1｜日期：2026-09-25｜状态：新增业务验收场景，业务测试尚未执行

## 1. 验收策略

先验证用户闭环、事实正确和数据隔离，再验证性能与体验。使用合成数据和明确授权的内测数据；不把生产健康信息复制到开发环境。功能测试与模型评测分别记录，模型回答通过不能替代事务测试。

## 3. 分层测试

Agent优化新增AG01—AG09案例，以19第10节为准，覆盖检查点前宕机、重复确认、租约过期、记忆纠错、证据撤回、预算终止、部分成功、注销和取消。进入G2前必须在真实PostgreSQL事务与多worker环境验证，内存图冒烟不能替代。

功能细化新增[24-业务场景与验收案例](24-业务场景与验收案例.md)B01—B28，覆盖23全部BR-01—BR-16。优先自动化计划并发采纳、实时会话唯一性、完整补录、部分完成、组归属、断网冲突、revision更新、授权撤回和删除；界面恢复与用户理解由人工配合。计时组不进入A0、仅热身不算work训练、日期型补录不伪造时长作为明确断言。

领域单元测试覆盖状态机、单位、算法和版本冲突；数据库集成测试使用真实PostgreSQL/pgvector而非内存替身验证约束。API契约测试锁定07的状态码、包络和分页。端到端验证“建档→计划→训练→反馈”，以及模型不可用时记录仍可用。

事件故障注入覆盖提交后发布前宕机、发布后标记前宕机、消费成功ACK前宕机、Redis停机、重复/乱序/死信重放。每种情形都核对事实数、投影revision和通知次数。

## 4. AI、性能与设备

AI评测采用08的200例与阈值，严重风险错误单例即阻止发布，专家审核疑似错误；同时记录错因，不仅给平均分。供应商漂移、提示词和知识发布均触发关键回归。

性能条件按02执行，记录环境配置、数据规模、并发模型、p50/p95/p99、错误率和单位成本。100并发用户不等于100个同时模型生成任务，分别压测。连续30分钟压测并附原始报告。

真机至少覆盖iOS与Android各两款、高低性能设备、微信当前及目标最低基础库。网络覆盖离线、弱网、4G、Wi-Fi；验证SVG/Canvas、命中区域、字体放大、键盘和后台计时。

## 5. 发布门槛

- 所有P0功能通过，无开放P0/P1缺陷（P1为影响核心路径且无合理替代的严重缺陷）。
- 跨用户读取、重复训练事实、严重危险建议在验收集上均为0。
- 内容和肌肉映射经过指定专家签字；媒体许可已核对。
- 性能达到02目标，或用户书面接受记录明确的偏差。
- 完成备份恢复、删除链路、回滚、费用熔断演练。
- 项目负责人批准相应阶段发布，文档批准不替代上线批准。

## 6. 验收报告模板

记录版本/构建ID、测试日期、负责人、数据与模型版本、用例总数/通过/失败/阻塞、缺陷链接、性能结果、AI评测、残余风险、放行结论、审批人和日期。已有Conda环境及框架冒烟结果见20；业务应用和数据库事务未实现，因此T/AG/B业务验收结果均为“尚未执行”，不能用环境验证代替。

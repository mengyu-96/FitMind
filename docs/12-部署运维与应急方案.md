# 部署运维与应急方案

版本：v1.0｜日期：2026-09-25｜状态：C01—C10建议方案已由用户确认

## 1. 环境与拓扑

开发、测试、生产分别使用独立数据库、对象存储空间、模型密钥和微信配置。建议内测采用反向代理+API容器+Worker容器+Redis，PostgreSQL优先托管或专机；知识文件与媒体放对象存储。生产数据不进入开发环境。

首轮容量假设1000注册用户、日活200、同时在线100、同时AI生成20，均为容量设计输入，不代表已获得用户。API可从2实例、每实例2核4GB起评估；数据库/Redis规格以压测决定，不能把此初值当性能保证。Compose单宿主无法避免整机停机，需要接受内测可用性目标或增加冗余预算。

## 2. 配置与发布

配置包括数据库连接、Redis、对象存储、模型/embedding版本、限流、费用阈值、知识版本、通知开关；密钥由运行环境注入，不进入仓库或小程序包。默认关闭外部通知和支付，通过审批后按环境开启。

建议CI顺序：静态检查→单元/集成/契约测试→依赖和密钥扫描→构建不可变镜像→测试环境部署→冒烟及关键AI回归→人工放行生产→灰度→观察。流水线平台待仓库托管确认，GitHub Actions是原稿候选而非已经存在的资源。

数据库变更采取先扩展后收缩：新增兼容字段→双读/回填→切换→后续删除旧字段。发布前核对备份和回退方案，不能对已有事实执行未经验证的破坏性迁移。

## 3. 监控与告警

| 指标 | 建议告警阈值 | 处置 |
|---|---|---|
| 核心API错误率 | 5分钟>2%且请求数≥100 | 查看依赖、回退新版本 |
| 非AI API p95 | 连续10分钟>1s | 慢查询、连接池、扩容 |
| outbox最老未处理 | >60秒 | 查发布器/Redis；>10分钟升级事件 |
| AI失败率 | 5分钟>10%且调用≥20 | 熔断、已评测备选、展示降级 |
| 单日模型成本 | 预算80%/100% | 预警/关闭非必要生成并限制调用 |
| 备份 | 超过26小时无成功备份 | 人工补备并查原因 |
| 空间 | 使用率>80% | 清理到期日志、扩容 |
| 内容安全/隐私 | 确认严重事件任意1例 | 停止相关能力并响应 |

日志仅含request_id/trace_id、接口、耗时、错误码、脱敏资源标识、版本和token成本；用户文本不作为默认日志。监控看板区分供应商等待与本地处理时间。

## 4. 备份与恢复

建议每日加密全量备份，滚动30天保留，生产上线前至少完整恢复一次，此后每月演练。RPO≤24h/RTO≤4h必须有演练证据；需要更低数据丢失窗口则启用WAL持续归档和PITR，并重新估算费用。

恢复流程：隔离新环境→恢复数据库/对象→重放删除和撤权清单→校验用户隔离与事实数→重建向量/肌肉投影→恢复outbox消费者→冒烟→切流。删除清单存放在不会随旧备份回滚的受控位置，按最小必要原则保留。

## 5. 故障运行手册

模型不可用：打开降级开关，保留训练记录，停止主动生成，恢复后不批量发送过期提醒。Redis不可用：核心事务继续写outbox，恢复消费后按事实重算。数据库不可用：拒绝写入并明确未保存，禁止在前端显示成功。

错误知识发布：撤回文档版本、失效缓存、追踪受影响引用，专家更正后新版本发布。坏应用发布：停止灰度、回退上一镜像；若存在不兼容数据迁移先使用兼容修复，不能盲目回滚数据库丢弃新训练。

## 6. 运营责任

上线前指定发布负责人、值班联系人、内容安全联系人和数据请求处理人。告警渠道、实际响应时段、应急授权范围待确认。本轮不创建云资源、域名、流水线或定时服务。

本地后端已按用户授权创建独立Conda Python3.12环境，操作与版本见[20-本地环境与验证记录](20-本地环境与验证记录.md)。LangGraph运行时默认不启用LangSmith等远程追踪；生产观测采用脱敏本地/受控日志，任何外部追踪服务须先核定数据用途和供应商范围。

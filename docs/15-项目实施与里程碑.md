# 项目实施与里程碑

版本：v1.0｜日期：2026-09-25｜状态：C01—C10建议方案已由用户确认；相对排期，尚未开始

## 1. 排期前提

建议MVP12周，从G0文档批准且明确授权开发后的第一个工作周起算，不设置已经生效的日历开工日期。前提为1名前端、1名后端/AI、0.5产品设计、0.5测试运维和兼职领域专家可投入，主体/账号/内容授权不长期阻塞。

单人实施或首版增加支付、语音、精细人体建模、多场馆均需重估。各角色可由同一人兼任，但关键审核应有独立复核。

## 2. 工作包与交付

| 阶段 | 周期 | 工作包 | 可评审产物/依赖 |
|---|---|---|---|
| G0 文档冻结 | 开工前 | C01—C10已确认，完成Agent优化与v1.0同步 | v1.0基线；当前已授权文档优化与环境准备 |
| G1 技术与体验验证 | W1—W2 | 真机热力图、模型对比、建档原型、10动作样本、数据契约 | 验证报告；选型/视觉确认 |
| 基础闭环 | W3—W4 | 登录授权、用户隔离、卡片、训练事实、幂等、outbox | 可手工记录并恢复的端到端闭环 |
| 智能教练 | W5—W6 | 对话编排、计划草稿与采纳、RAG与引用、纠错记忆 | 可用对话闭环；初版AI评测 |
| 可视化与管理 | W7—W8 | 肌肉重算、前后图、动作设备详情、内容管理、站内提醒 | 算法/内容专家审核；完整功能演示 |
| G2 内测准备 | W9—W10 | 导出注销、安全/并发/弱网测试、恢复演练、种子内测 | 30—50人受控内测与问题清单 |
| MVP验收 | W11—W12 | 修复、留存观察、成本报告、审核材料 | 按11验收；下一阶段决策 |
| G3 商业试点 | MVP后另估4—6周 | 支付规则确认、权益/退款、定价实验 | 支付验收和真实转化数据 |
| G4 扩大上线 | 达商业与合规门槛后 | 扩容、渠道试点、公开发布审批 | 上线批准与运行责任 |

12周内只能观察早期队列留存，不能声称已有稳定年度留存或规模化盈利。若内容授权未完成，技术可内部演示，但不向用户发布无许可内容。

## 3. 关键路径

范围确认→接口/数据冻结→训练事实可靠写入→Agent工具对接→肌肉投影与前端联调→安全和数据删除→内测验收。另一条并行依赖为内容授权→专家审稿→知识入库→引用与安全评测；任何一条延误都影响发布。

## 4. 职责分工

| 事项 | 执行负责人 | 最终确认 |
|---|---|---|
| 范围、预算、发布 | 产品/项目负责人 | 用户/项目发起人 |
| 前端、交互、真机 | 前端 | 产品负责人 |
| 领域、数据、API、运维 | 后端/AI及运维 | 技术负责人 |
| 知识、映射、风险建议 | 内容编辑与健身专家 | 独立专家审核人 |
| 用例、缺陷、验收报告 | 测试 | 项目负责人 |
| 主体、协议、供应商数据条款 | 法务支持 | 主体负责人 |

角色姓名和可投入时间全部待确认。AI辅助开发可以提高效率，但不替代专家内容审核和主体责任。

## 5. 任务完成定义

功能实现需同步契约、测试、错误处理、日志与文档，代码评审通过且满足关联验收用例。演示成功但无异常测试不算完成；模型回复正确但未写入事实不算完成。

每周检查已交付产物、阻塞、剩余估算、成本与范围变更。需求变化先按17评估，不暗中增加首版范围。当前已接受C01—C10，Agent设计优化与Conda环境准备进入执行；业务功能、模型实测和G1真机验证尚未完成，不能标记整个G1通过。

# 项目实施与里程碑

版本：v1.3｜日期：2026-09-25｜状态：M0微信小程序分阶段交付；保留原排期情景，尚未开始开发

当前交付以本页§7及[29](29-微信小程序首版收束与智能体授权.md)为准。§1—6保留原完整范围的人力和排期依据，不作为当前M0全量施工清单；热力图、实时工作台、后台触达与管理Web后置。

## 1. 原完整范围的排期前提

原范围采用12周情景，前提为1名前端、1名后端/AI、0.5产品设计、0.5测试运维和兼职领域专家可投入，主体/账号/内容授权不长期阻塞。M0收束后重新按实际人力与验证结果估时，不沿用12周作为新承诺；开工仍从文档确认并明确授权开发后起算。

单人实施或首版增加支付、语音、精细人体建模、多场馆均需重估。各角色可由同一人兼任，但关键审核应有独立复核。

## 3. 关键路径

范围确认→接口/数据冻结→训练事实可靠写入→Agent工具对接→肌肉投影与前端联调→安全和数据删除→内测验收。另一条并行依赖为内容授权→专家审稿→知识入库→引用与安全评测；任何一条延误都影响发布。

## 4. 职责分工

| 事项 | 执行负责人 | 最终确认 |
|---|---|---|
| 范围、预算、发布 | 产品/项目负责人 | 用户/项目发起人 |
| 前端、交互、真机 | 前端 | 产品负责人 |
| 领域、数据、API、运维 | 后端/AI及运维 | 技术负责人 |
| 知识、映射、风险建议 | 内容编辑与健身专家 | 独立专家审核人 |
| 用例、缺陷、验收报告 | 测试 | 项目负责人 |
| 主体、协议、供应商数据条款 | 法务支持 | 主体负责人 |

角色姓名和可投入时间全部待确认。AI辅助开发可以提高效率，但不替代专家内容审核和主体责任。

## 5. 任务完成定义

功能实现需同步契约、测试、错误处理、日志与文档，代码评审通过且满足关联验收用例。演示成功但无异常测试不算完成；模型回复正确但未写入事实不算完成。

每周检查已交付产物、阻塞、剩余估算、成本与范围变更。需求变化先按17评估，不暗中增加首版范围。当前已接受C01—C10，Agent设计优化与Conda环境准备进入执行；业务功能、模型实测和G1真机验证尚未完成，不能标记整个G1通过。

## 6. v1.2工作包与阶段校准

G0冻结当前审阅后的文档修订，不退回v1.0旧字段契约。G1用“自由记录→主动反馈/提问→自然回答→同对象补充→可用投影”验证一条纵向闭环，包含未知kind、拒答与无模型保存；建档原型改为渐进了解原型。

基础闭环新增源对象/证据/语义补丁/投影绑定与跨run operation回执；智能教练新增通用规划器、任务档预算、有限委托、关注议程/答案吸收；提醒阶段增加相关性与答案并发去重；治理覆盖新增个人对象全链路导出删除。AF/PQ与原T/AG/B共同纳入验收。

这些工作包属于实现路径的实质深化，G1结束后按原型证据重估人日与关键路径；12周为原基准假设，未证明能在相同资源下容纳全部新增复杂度。先交付统一事实写入与主动对话，再扩展适配器和视图，不能先写一批固定表单再用补丁掩盖架构差异。

| 阶段 | 当前工作包 | 可审阅交付与进入下一步的证据 |
|---|---|---|

| 可靠闭环 | 源对象/修订、简洁记录与历史、消息/operation幂等、取消恢复、基本数据治理 | 模型故障不丢记录；微信前后台/弱网不重复提交；跨用户隔离 |
| 自主教练 | 单次/日期/有序计划、局部更正、前台持续委托、主动提问/反馈、基本动态卡 | 在已授范围直接执行并展示可撤销差异；用户停止后后续动作被阻断 |
| M0内测准备 | 来源/内容撤回、导出删除、错误恢复、真机及适用AI评测 | M001—M008与原用例适用断言通过；关键业务事务和数据治理真实验证 |
| M0受控内测 | 小规模微信小程序体验版，观察记录省力程度、任务完成与互动负担 | 缺陷/成本/首次价值报告；正式公开发布另过主体与平台审核 |
| V1专项候选 | 热力图/算法、实时工作台、后台回访、管理Web、商业支付分别排期 | 每项根据内测需求、依赖及专业/平台验证单独进入，不捆绑全部首发 |

当前关键路径为微信交互→可靠源记录→开放工具执行→简洁计划/主动反馈→隐私与真机验收。审核内容是并行必要依赖；人体图资产与订阅消息不阻塞M0。编排先用主规划循环，不先建多Agent平台、通用工作流编辑器或Schema管理系统。

当前任务和持续委托的授权表达须首先验证，不能实现到最后才把“能提建议”升级为“能执行”。每个工作包同时验证授权内办成事情与范围外正确停下，指标不以工具调用越少越好衡量。

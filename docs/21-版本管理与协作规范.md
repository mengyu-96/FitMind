# 版本管理与协作规范

版本：v1.0｜日期：2026-09-25｜状态：已生效

## 仓库基线

- 远程：`git@github.com:mengyu-96/FitMind.git`
- 主分支：`main`，用于可交付基线。
- 当前基线提交：`2d487fa docs: establish FitMind project baseline`
- 本地 Git 可执行文件：`D:\Git\cmd\git.exe`。
- 提交前使用项目 Python 环境运行验证脚本和静态检查。

## 分支与提交

功能使用 `feature/<topic>`，缺陷使用 `fix/<topic>`，文档使用 `docs/<topic>`，实验使用 `experiment/<topic>`。完成后通过合并请求进入 `main`；禁止直接重写已推送的 `main` 历史。

提交信息采用 `type: summary`：`docs`、`feat`、`fix`、`test`、`refactor`、`chore`、`build`。一次提交保持一个目的，提交正文注明关联需求、迁移和验证命令。当前首个提交只包含项目文档、后端环境定义及环境验证脚本。

## 发布与标签

文档/设计基线使用 `docs-vX.Y`，MVP验收使用 `mvp-vX.Y.Z`；只有完成对应验收门槛才创建标签。版本号遵循：破坏范围或接口升主版本，新增兼容能力升次版本，错误修复升补丁版本。用户确认C01—C10形成计划基线v1.0，Git仓库代码基线仍由提交和标签管理，不把文档版本等同于可运行软件版本。

## 提交前检查

```powershell
& '.\.conda\fitmind-backend\python.exe' -m pip check
& '.\.conda\fitmind-backend\python.exe' -m ruff check backend
& '.\.conda\fitmind-backend\python.exe' '.\backend\scripts\verify_environment.py'
$git = 'D:\Git\cmd\git.exe'
& $git -c safe.directory='D:/work/FitMind' status --short
& $git -c safe.directory='D:/work/FitMind' diff --check
```

不提交`.conda`、缓存、密钥、`.env`、用户数据、模型输出和未经授权的媒体。`.gitignore`负责常见本地文件，提交者仍需检查`git status`。发现密钥后立即撤销并轮换，不能只删除文件后继续使用。

## 远程操作

统一使用SSH远程地址。常用检查：

```powershell
ssh -T git@github.com
& 'D:\Git\cmd\git.exe' -c safe.directory='D:/work/FitMind' remote -v
```

推送前确认分支和差异；优先普通`git push`，禁止`--force`覆盖共享历史。当前仓库已完成首次`main`推送并设置`origin/main`跟踪。

# 功能详细设计与用户流程

版本：v1.2｜日期：2026-09-25｜状态：开放业务与主动教练功能细化，尚未实现

## 1. 使用方法与范围

本文回答每个功能“从哪里进入、需要什么信息、怎么完成、出错怎么办”。03管理产品范围，本文管理操作流程，23管理跨模块业务规则，24提供可执行验收场景。沿用F01—F15需求编号，不新增收费、社交、语音、动作识别、多场馆等首发范围。

功能分为公共内容、个人记录、个性化教练三层。公共内容允许游客浏览；个人记录需要登录和用途授权；个性化教练按实际使用信息检查相关用途及当前任务证据。用户未完整建档也可通过自然语言记录和请求帮助。所有源信息先走25的开放对象，标准表只承载可适配投影；26补充32个开放场景，28定义主动提问反馈。

## 2. 登录、服务资格与授权（F02/F11）

**入口**：首次使用个人能力或“我的”。**完成标志**：服务端建立有效会话，并返回当前可用能力集合capabilities。

1. 游客可以看审核后的动作、设备与通用知识。点“加入我的训练”“生成计划”时再登录，成功后回到原动作。
2. 展示协议、数据用途和成年服务范围。成年资格使用用户声明，不额外收集身份证；声明未成年则不开放个性训练能力，保留公共浏览。
3. 用户按用途授权，服务端记录policy_version。拒绝通知不会阻断训练；拒绝AI处理仍可在个人记录授权有效时手工记录。
4. 登录失败保留当前公共页面；微信code过期重新获取，不把code/session_key当长期登录凭证。
5. 退出清理个人缓存和当前会话；不等于注销账号。切换账号后不带入上一账号离线草稿。

首次授权不预勾选。字段授权与功能可用性对照见23 BR-01；政策更新仅对有实质变化的处理重新征求同意，不让用户每次启动重复确认。

## 3. 对话建档与目标管理（F02/F10）

**入口**：任一当前任务、主动探索话题、资料页或目标变更。**产物**：有来源的个人对象与渐进profile投影；无需先完成一轮统一问卷。onboarding_status仅作历史旅程标记。

| 信息 | 何时需要 | 表达方式与缺失处理 |
|---|---|---|
| 成年资格 | 开放成人个人训练服务时 | 服务资格声明，不要求更多无关身份字段 |
| 主要目标 | 需要目标取舍时 | 自由表达、多个目标可并存；常用分类仅作标签 |
| 训练经验 | 具体建议依赖经验时 | 已有相关记录可作为证据；未知时避免超出依据的负荷建议 |
| 可训练时间 | 编排时段/总时长时 | 单次可用时间足够就不追问整周；轮换方案可无固定日期 |
| 可用器材 | 动作选择依赖器材时 | 可从当前场景获知；未知时先提供候选或问最关键一点 |
| 当前训练限制 | 决定相关个性负荷/适用动作时 | 对未知/拒绝不视作无伤；仅限制依赖缺失信息的建议，不封锁记录与一般说明 |
| 身高、体重、围度 | 可选 | 不影响基础记录；缺体重不估算热量 |
| 具体成绩、偏好 | 可选 | 缺失时计划不填虚构重量，可让用户选择可控负重 |

每轮默认优先一个有价值问题，允许0—2问或用户希望的深入访谈；这是交流偏好，不是固定流程上限。Agent主动解释观察、询问体验、探索目标，并记住已回答/拒绝/不确定事项。用户信息先保存，待问事项进入inquiry_agenda；提取保留来源和归因，模型推断单列候选。

目标变更流程：保存明确新目标→识别实际受影响计划依赖→必要时提出局部调整。明确指令/已有委托覆盖的可逆变更可直接验证执行并反馈；重大目标改动或实际歧义才确认。不能把用户回答一项探索问题等同于接受整份新计划或长期委托。

**异常**：用户“暂时不想说膝盖情况”保留declined状态，不当成“无伤”；“之前说错了”定位冲突字段再改。对已有计划的影响以23 BR-03处理。

## 4. 教练对话与任务处理（F01/F10）

输入框支持文字和快捷回复。消息状态为local_pending/sending/accepted/failed；Agent运行状态另行显示，消息已送达不等于训练已保存。用户可以阅读历史、重试原消息、取消当前生成、从卡片继续讨论。

| 意图 | 正常动作 | 需要澄清的情形 |
|---|---|---|
| “记录今天卧推4组10次60kg” | 先存原述，定位动作并映射有依据的组 | 仅对口径/归属有歧义部分提问，不拒绝整条记录 |
| “刚才是50，不是60” | 展示被改记录、创建修订 | 不知道改哪次、哪组 |
| “明天只有20分钟” | 基于旧计划生成压缩草稿 | 日期时区不清或限制无法满足 |
| “这个动作怎么做” | 以页面绑定exercise_id检索 | 脱离页面且有多个“这个” |
| “删掉刚才那张” | 根据上下文定位卡片后删除 | 不确定是卡片、消息还是训练事实 |
| “今天膝盖疼” | 暂停相关推荐、记录用户自述限制（已授权时） | 不将疼痛自动归因或诊断 |

一次消息含多任务时按依赖执行，UI逐项显示结果。例如训练记录成功、新计划失败，应展示“训练已保存；计划未更新”，让用户单独重试计划。重试按钮携带原消息/动作ID，不复制整段用户输入造成新事实。

只读问题不弹确认；明确自述即使不完整也可保存；单位歧义只影响相应投影。明确意图/有限委托内调整不重复确认，删除历史等按23 BR-04处理。Agent可在答复后主动问最相关的新问题，或先反馈观察再验证；等待确认不锁死其他话题。

## 5. 计划生成、采纳与调整（F04）

**入口**：即时需求、训练页、自由目标、Agent主动提出并获用户接受的规划方向。**前置**：授权有效，具体可执行建议具备其适用证据；无统一必需画像字段清单。

### 5.1 计划内容

MVP允许单次、自由天数、按次轮换、条件节点及多模块计划；7日仅为默认模板之一。复杂专业周期化规则仍需审核，不因数据结构灵活就宣称专业方法已验证。没有日期的节点不生成missed或定时提醒；开始执行/调度时按任务物化明确安排。

计划payload由Agent组织段落、模块、候选与关系；只有需要执行、调度或计算的节点才投影必要字段。组计划需要目标组/计量等证据；休息、技能学习、开放目标不强行填写组数。可选信息不生成默认事实，计划项不创建已完成训练记录。

### 5.2 主流程

生成请求引用相关对象版本→按需检索→形成灵活方案和可执行变化集→逐操作校验证据/适用性/权限→预算内修复或缩小到可用部分→按明确意图/委托执行或展示提议→更新未来安排及已授权提醒。无需每次重建整张周表；修复次数由任务预算和是否有进展决定。

草稿失败保留旧计划；用户修改草稿后必须重新校验。展示“建议60分钟”却包含90分钟内容不允许采纳；预计总时长包含组内估计、休息和切换，并标为估计。

### 5.3 调整及冲突

| 操作 | 行为 | 不自动发生的事 |
|---|---|---|
| 替换动作 | 选择已审且条件匹配动作生成变化集，当前意图/委托内验证执行并反馈 | 不复制旧动作重量到新动作 |
| 改日期/缩短训练 | 修改未来项目或进行中尚未执行目标，保留原快照及调整版本 | 不将两次训练自动合成一次 |
| 当天没练 | 过期计划项记missed，允许用户后续调整 | 不自动累积到次日、不惩罚性加量 |
| 开始后换主计划 | 新主计划影响未来；进行中会话保持快照 | 不删除已经记录的组 |
| 偏好变化 | 只重审真正依赖该偏好的部分，委托内可调整 | 不让标题/无关偏好变化阻断全部训练 |
| 新增限制/内容撤回 | 相关未来计划项暂停启动并提示复核 | 不因为已采纳过就继续推荐撤回动作 |

用户可归档active计划后做自由训练；归档不删历史。计划项目迁移、跨版本关联和履约统计以23 BR-05/BR-06为准。

## 6. 训练执行、补录与纠错（F05）

### 6.1 开始与执行

入口为计划项“开始训练”、自由训练或对话补录。服务端最多允许一个实时in_progress/paused会话；已存在则提供继续或结束入口。draft允许多个。历史补录不占实时训练名额。

计划执行保留目标快照。用户文字、明确按钮操作和直接录入都是事实来源；不要求勾选固定表格才算报告完成。标准组投影用entry_id区分动作出现、set_id识别组；灵活对象还可保存组合练法、非库动作和没有组明细的自述。

| 项目 | 输入方式 | 记录规则 |
|---|---|---|
| 次数组 | 次数、负重口径、重量；RPE可选 | 完成时次数为正整数，负重缺失不得补0 |
| 计时组 | duration_seconds；重量仅动作需要时填写 | 不用“次数=1”冒充30秒动作 |
| 热身组 | 显式set_kind=warmup | 保留历史，不参与A0负荷与有效工作组统计 |
| 跳过动作 | 标记skipped及可选原因 | 不创建完成组，允许恢复为pending |
| 暂停/休息 | 记录时刻、暂停区间 | 后台计时根据时刻恢复，非持续计时器 |

负重有歧义先保存原述，只有当前任务需要该口径时才追问“每只还是总重”；同一器械不同型号不默认成绩可比。计划建议与实际完成分开，没有实际证据不能照抄计划。

### 6.2 结束与部分完成

标准组训练的“结束并保存”展示已录组与未完成项；有合格组可提交标准completed会话。用户明确说已经练完但没有组细节时，开放源记录可标finished并正式保存，projection_status=partial/none；界面说明暂不能算组完成率，而不是拒绝保存。只有用户确实未做且无活动内容时保留草稿/取消。partial指完成范围，不等于保存失败。

有已完成组的会话点击“取消训练”先提示“保存已完成部分 / 放弃本次记录”；选择保存走complete，明确放弃才cancelled。cancelled内容不计入历史统计或肌肉估算；误取消恢复不在MVP自动支持，用户可按原信息新建补录且明确其来源。

结束后的即时结果：训练已保存、有效组/热身组数量、实际时长（若可确定）、计划履约状态；肌肉投影可能显示更新中。不能因投影失败把已提交训练显示为保存失败。

### 6.3 补录与纠错

“昨天完成……”即使细节不全也可成为正式源记录；能规范化的部分通过retroactive适配创建标准会话/组，不虚构实时开始。时间可date/range/unknown，有日期的算法估算锚点按23处理；范围未知的记录不硬分配某日。补齐沿同一activity_id，不重复增加训练次数。

系统发现同日同动作相似记录只提示“可能重复”，不能自动去重掉真实重复训练。用户选择关联已有会话、创建独立会话或取消。技术重试依据客户端ID幂等，不依赖语义相似度。

纠正记录允许自然语言语义patch：读取相关对象版本→定位修改目标→验证来源及授权→服务器构建完整修订和受影响投影→旧结果失效/重算。无需让用户或Agent重填全部会话。无法定位时只澄清归属；删除卡片/提醒不删源训练。

## 7. 资料卡与首页个性化（F03）

资料卡是开放对象的视图：笔记、偏好、目标、训练和自定义信息都能由Agent组合展示。owned卡的实际内容也由源对象管理，reference卡引用其他对象/投影；编辑产生源对象changeset，禁止直接改快照冒充事实。可把多个对象组合成一张卡，也可用纯文字呈现。

用户可置顶/取消置顶、移动、隐藏、归档、删除单张卡。MVP的置顶是一个独立属性，不提供批量任意排序；P1再支持批量重排、合并和拆分。排序为用户置顶优先→Agent priority降序→创建时间升序→ID稳定排序。用户隐藏/归档后Agent不能反复自动恢复，除非用户提出恢复。

安全/同步错误有稳定状态入口；源删除后不展示旧快照。未知业务kind不拒绝展示，自定义schema是可选描述，payload开放；组件树在受控原语中自由组合。大小/节点预算约束资源，不借此要求全部用户只填预设字段。

## 8. 肌肉面板、历史与复盘（F06/F10）

训练首页显示今日计划、进行中训练、最近事实和肌肉摘要。热力图支持前后视图、图例、区域选择、列表替代；详情展示估算值、置信等级、最后训练、近7天会话数、相关动作与来源记录。

| 情况 | 用户看到的内容 |
|---|---|
| 没有可用训练 | 数据不足，提示记录第一条；不显示100%恢复 |
| 有记录但无肌肉映射 | 展示该记录，说明未纳入部分估算 |
| 新事实等待重算 | “记录已保存，图表更新中”，旧快照带时间 |
| 重算失败 | 可查看历史与再次刷新；不建议依据旧数值加量 |
| 有疼痛自述 | 独立提示，不因绿色热力图消失 |

历史按发生时间浏览，显示补录标记；过滤动作、时间范围、有效/已取消（默认只有效）。跨日训练按开始所在当地日期归属，补录按用户声明日期；统计细节见23 BR-08。

周复盘按需生成，不增加自动推送。输入为已完成事实、目标、有效计划项和数据缺口，输出训练次数、计划覆盖、动作表现及可执行的下一步。没有可比样本则“尚无法判断趋势”。报告保存输入revision；修订后原报告标过期，不让旧结论覆盖新数据。

## 9. 动作、器械与知识（F07/F08）

动作可按名称、别名、器材、目标区域筛选。详情包含标准做法、常见错误、限制、可用替代和引用；替代动作是候选，不是自动替换。没有设备型号/位置时只展示通用说明；具体场馆位置仍为后续阶段。

点击“加入训练”时先选择当前未结束会话或自由训练草稿；加入仅增加计划条目，不等于做完。动作撤回后不得加入新计划或新训练，历史名称与发生时版本保留用于审计，撤回指导文案不继续展示。

引用面板展示标题、版本、段落/页码定位及合法摘录。通用用户反馈可以选择“内容不准确/不适合我的情况/来源不可用/其他”；反馈不直接修改公开知识。没有证据的问题明确说明，保留记录/浏览等其他能力。

## 10. 提醒与反馈回访（F09）

主动性首先发生在会话内：Agent可以主动发现训练变化、解释观察、询问体验并维护关注议程，不以用户先发送“请问我”作为前提。提问依据、语境、答案采纳、多主题关联、重复抑制和个性交流偏好详见28。后台提醒只是主动教练的一种渠道。

首次开启后台提醒需要用途与时间偏好；默认支持计划、感受、久未训练，并允许Agent依据上下文创建其他personal关注点。触发器仍由平台安全注册，语义类别不必固定三选一；外部订阅消息独立授权。

用户可标记站内信已读，或在提醒设置中将尚未投递的候选延后一次、关闭该类提醒。MVP不从已投递站内信再次生成同一条通知。延后到静默区间则顺延，晚于业务有效期则取消。用户已经完成计划项时取消尚未投递提醒；已生成站内信保留为历史并显示状态已变化，不能改写为新的催促。

每日1条、间隔20小时为后台初始预算，不是会话内自然主动问话的上限。用户偏好和服务端策略可调整，Agent不能自己放大；发送前复核授权、业务相关性、议程是否已回答/拒绝、频控和不适信息。优先级依据当前信息价值决定，旧三类排序只是默认例子。

## 11. 数据管理与退出（F11）

设置提供查看授权、撤回、导出、单条删除和注销。撤回AI处理停止新个性生成并取消待确认AI动作；是否同时删除现存数据由用户选择，不能混为一个按钮。撤回个人训练数据处理后停止训练及派生处理，保留数据管理入口进行导出/删除。

导出需要近期再认证，包含开放对象、claims来源与自定义schema/单位、关系、委托/议程、画像、计划、训练及投影版本；不能只导出固定表导致自定义信息丢失。不含密钥、他人内容或未获许可公共教材。注销覆盖这些新增对象与派生副本。

注销前提示不可恢复范围并再认证，接受请求后立即撤销会话、阻断查询、停止Agent/提醒、吊销导出链接；后台按保留策略清理数据库、向量、对象和备份删除清单。不能因为物理清理排队而允许旧令牌继续读取。

## 12. 内容管理工作台（F15）

内部账号使用独立角色授权，不让普通用户通过前端参数申请审核员。内容编辑创建动作、设备和知识草稿，关联授权证明、来源和适用条件；提交后编辑冻结，需要修改则撤回为draft并使原审核失效。

审核员查看内容差异、引用与许可，批准或驳回并注明原因；不能自审。发布前确认检索索引就绪，最终原子切换published指针；索引失败保持旧发布版本。撤回立即阻断新查询/新建议，异步清理缓存和向量不能成为前台阻断的前置。

反馈队列状态open/in_review/resolved/rejected，处理结论和用户可读说明分开。对于安全问题可先撤回再修复。用户看到“已收到/处理中/已处理”的真实状态，不承诺专家已读尚未处理的反馈。

## 13. 后续商业功能边界（F12—F14）

会员与B端仍按已确认分期：V1准备SKU、订单、支付、权益、退款和对账；V2准备场馆/教练授权、多租户。MVP不出现可付款但无法履约的入口，价格研究标明尚未开放购买。付费失败、到期或退款不影响用户访问和导出自己的历史记录。

后续商业PRD必须明确试用转正式、自动续费、到期时区、部分退款和权益回收规则后才接真实渠道；当前不把这些未验证渠道能力写成已实现流程。

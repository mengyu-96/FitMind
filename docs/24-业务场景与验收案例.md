# 业务场景与验收案例

版本：v1.1｜日期：2026-09-25｜状态：业务验收规格，非已通过测试报告

## 1. 测试数据与执行方式

使用合成用户A/B、已审核动作EX-A（杠铃次数组）、EX-B（哑铃次数组）、EX-C（自重计时动作）、未发布动作EX-D；所有ID在测试环境生成。初始时区Asia/Shanghai；测试时钟可固定但生产不得信任客户端时间。RPE、重量与算法参数仅用于验证存储计算，不是训练推荐。

每个案例需要检查用户界面、HTTP结果、数据库事实与版本、事件/outbox、派生状态及权限。以下预期用于后续自动测试与人工验收；当前仅完成文档检查。案例B01—B28对应23中的BR规则，旧T01—T13、AG01—AG09继续有效。

### B06：限制信息不能被估算颜色覆盖

Given：A的某区域fatigue=20，显示估算低疲劳；有效计划包含相关动作。When：A说明当前疼痛，随后问“既然是绿色能不能加重量”。Then：记录为用户自述而非诊断；计划资格被阻断或要求复核；不建议依据绿色加量；仍能保存已完成训练。若无法确定限制关联动作，先阻断未来个性计划启动再澄清。追踪F04/F06，BR-03。

## 3. 计划和训练执行

### B07：并发采纳不能覆盖另一份刚确认的计划

Given：当前active=P1，两个draft P2/P3均声明expected_active_plan_id=P1。When：两次采纳并发提交。Then：恰有一个成功、一个409 ACTIVE_PLAN_CHANGED；最终只有一个active，失败草稿保留；outbox只为成功采纳创建一份事件。追踪F04，BR-05。

### B08：换计划保留已经开始的训练

Given：A正在按P1/O1训练，已经记录2组；P2调整未来O2。When：采纳P2。Then：当前会话继续引用P1/O1快照及原plan_set_id；已录组不丢；未改动的未来项复用ID，发生变动的O2取消并建立新项；不为进行中的O1生成一个新的重复安排。追踪F04/F05，BR-05/06。

### B09：部分完成不是取消，也不是保存失败

Given：计划4个work目标组，A实际完成2组。When：点结束并保存。Then：会话completed、completion_kind=partial，occurrence为partial，组完成率2/4=50%；生成一次训练事件；未完成2组不进入负荷计算；响应已保存，即使projection_status=updating。追踪F05/F06，BR-06/07/11。

### B10：无训练和仅热身分别处理

Given：会话没有有效完成组。When：请求complete。Then：422 NO_COMPLETED_SETS，可选保留草稿/取消，不生成训练完成事件。

变体：只完成1组warmup。Then：允许保存真实会话、completion_kind=warmup_only；不进入北极星有效训练及A0负荷；有计划关联时显示partial及0个work目标完成。追踪F05，BR-07/15。

### B11：放弃已经做过的部分必须明确

Given：进行中会话有2个已完成work组。When：用户点击取消。Then：展示保存部分/放弃记录；保存部分走B09，明确放弃才cancelled，派生统计不增加。只关闭页面不触发cancelled。追踪F05，BR-04/07。

## 4. 时间、重试、离线与纠错

### B16：跨午夜重试不改“昨天”的含义

Given：消息在2026-09-25 23:59:50+08:00首次accepted，内容“昨天做了EX-A……”，数据完整且用户未提供时刻。When：25秒后跨午夜重试相同client_message_id。Then：仍只保存一份2026-09-24日期型训练；time_precision=date，真实started_at/ended_at为空，derived_effective_at=2026-09-24 23:59:59+08:00转UTC；时长不填24小时或模型猜值。追踪F01/F05，BR-04/08。

### B17：技术重试与真实重复训练不同

Given：同一client_session_id补录请求已提交，响应丢失。When：相同键重试20次。Then：返回同一session，training_revision只递增一次。

变体：用户第二次明确提交不同client_session_id、内容相似的另一场训练。Then：提示疑似重复并允许确认新建；不能凭相同动作重量静默合并。追踪F05，BR-04/09。

### B18：离线编辑遇到服务器已经完成

Given：设备A离线持version4并修改一组，设备B以version4完成训练得到version5。When：A恢复同步。Then：旧写409 VERSION_CONFLICT；前端展示服务器完成状态和本地修改差异；接受后调用修订而非重开会话；没有第二份训练或状态倒退。追踪F05，BR-09/12。

### B19：历史修订与删除重算

Given：会话S1/S2贡献到肌肉状态，投影source_revision=8，报告R1引用8。When：修订S1时使用正确会话version。Then：用户training_revision=9（不是把S1.version当全局版本），R1标过期，计算结果等于从有效S1修订+S2重算；旧revision8任务晚到不覆盖。

变体：删除S1。Then：立即不再查询到S1正文、卡片快照和语义记忆；训练revision再递增，履约按规则回算，不重发历史提醒。修订为零有效组返回422，提示改为删除。追踪F05/F06/F10，BR-11/12。

### B27：计划履约统计不因归档被改写

Given：本周到期4项：2项completed、1项partial且至少完成1个目标组、1项missed。When：用户周末归档主计划。Then：履约率仍3/4=75%，不会因归档变100%；组完成率独立计算。提前合法改期取消且未到期的旧项不重复计分母；到期后删除/归档不抹去missed。追踪F04/F10，BR-06/15。

### B28：跨模块完整旅程

新用户A按B03确认资料→生成并采纳7日计划→从O1开始→按B13澄清负重→断网记录一组→恢复同步→部分完成→等待投影更新→查看估算解释与来源→纠正一组→旧复盘标过期→修改目标得到新草稿→采纳时校验当前计划→关闭提醒→申请导出。

期望：每一步均有真实状态与返回入口；不因拒绝通知影响训练；只计算有效事实；消息重试不增加训练次数；计划变化不改写旧快照；导出版本与请求时快照一致。追踪F01—F11、BR-01—BR-16。

## 6. 错误码与前端行为验收

| code | HTTP | 必须提供的恢复方式 |
|---|---:|---|
| CONSENT_REQUIRED | 403 | 指明缺失用途，跳转授权或保留公共能力 |
| PROFILE_INCOMPLETE | 422 | missing_fields及一次最多2问的入口 |
| ACTIVE_PLAN_CHANGED | 409 | 最新active_plan_id与重新审阅入口 |
| PLAN_INPUT_STALE | 409 | 变化的版本类别，不含其他用户内容 |
| PLAN_REVIEW_REQUIRED | 409 | 受影响项与重新生成/调整入口 |
| ACTIVE_SESSION_EXISTS | 409 | 本人正在进行的会话ID |
| VERSION_CONFLICT | 409 | 当前version，重新读取再合并 |
| IDEMPOTENCY_CONFLICT | 409 | 不自动改用新键重试同一意图 |
| CONFIRMATION_EXPIRED | 409 | 重新生成预览，不悄悄执行 |
| NO_COMPLETED_SETS | 422 | 保留草稿或取消 |
| SOURCE_EDIT_REQUIRED | 422 | 源对象的安全导航信息 |
| CONTENT_UNAVAILABLE | 422 | 替代动作/公共目录，保留历史记录能力 |
| PROJECTION_PENDING | 非失败码 | 成功响应data.projection_status=updating；不显示训练保存失败 |

401和跨用户404不返回可猜测其他账号存在的信息。模型不可用时返回503或run.failed及retryable，但已提交工具回执仍可查询，避免用户重复做已成功操作。

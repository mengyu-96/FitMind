# 开放业务场景与能力协作设计

版本：v1.2｜日期：2026-09-25｜状态：业务设计深化；覆盖当前MVP及其边界，非穷尽所有现实情境

## 1. 场景设计原则

用“用户想完成什么”组织能力，不要求每个用户依次经过固定建档、选计划、填表。下列SC场景都给出Agent可选择的路径、可保存的内容、何时停止推断以及后续如何衔接。系统返回能力和证据缺口，Agent决定是否有必要当场追问。

跨场景通用动作：保存明确原述、补充用户语境、检索可用知识、草拟或变更对象、验证执行、组合视图、安排已授权回访。具体对象类型可以新建；权限、确认、真实训练事实与公开知识来源仍按25管理。

## 2. 从任意入口开始（SC-01—SC-04）

| 场景 | 用户示例 | Agent可选择的动作 | 业务结果与边界 |
|---|---|---|---|
| SC-01 直接提问 | “这台器械怎么调？” | 查通用器械资料，按缺口问型号或提供如何辨认 | 不先要求体重/目标；没有场馆资料不编位置 |
| SC-02 即时需求 | “今天就15分钟，活动一下” | 结合已知条件给单次方案；必要时只问器材/相关限制 | 无完整建档仍可得到适用范围明确的建议；不自动开长期计划 |
| SC-03 只想被记录 | “今天练腿，状态差，不想聊” | 保存训练自述和短期感受，简短回执 | 不追问组数；不把“不想聊”永久推断为性格 |
| SC-04 自由目标 | “下个月爬山能跟上朋友” | 建立自由目标对象，检索相关一般训练知识，逐步了解时间 | 不强制改成增肌/减脂；不保证达成或估计生理能力 |

对话结束不会要求“把资料填完再走”。首次可交付内容可以是有来源的回答、一条已保存记录或可用的一次训练建议；用户可随时从这些内容继续。

## 3. 不完整、多样、复合训练记录（SC-05—SC-09）

### SC-05 不记得重量

输入“做了4组卧推，每组10次，重量忘了”。保存用户原述、已知组次与动作候选；若动作可明确对应，适配器生成稳定组ID，weight_kg=null。A0若具备动作映射、完成证据、时间和work属性可计算覆盖部分；e1RM/吨位不可计算。没有“需要填写重量才能提交”的错误。

后续“是40kg杠铃总重”链接到同一对象版本，投影补齐，不新建第二次训练；若聊天上下文无法确定是哪一次，则先保存一个待关联补充，只有“归属”需澄清。

### SC-06 混合活动

输入“快走半小时、爬了几层楼，回家拉伸了一会”。可保存一个活动对象包含多个子活动和原始措辞，未计数的层数/拉伸时长保持未知；支持用户自述的距离、配速、坡度、心情等扩展字段。当前A0不支持的活动保留在历史和复盘中，不假造肌肉映射、热量或统一组数。

### SC-07 现场特殊练法

递减组、超级组、循环训练、暂停组、左右单侧等作为对象关系/segments记录；智能体可自行选择视图。只有能明确拆分并满足标准投影规则的部分进入计算。超级组的休息不能被复制到每个子动作导致时长倍增；左右侧必须有来源，不由镜像图推断。

### SC-08 自创动作名或新设备

用户说“做了健身房那个V把拉背机”。保留用户动作名和设备描述，检索候选但不自动确定exercise_id。匹配后更新同一记录；匹配失败也能正式保存。该记录不能让Agent将未审动作编成新的个性负荷建议，更不能自动发布到公共动作库。

### SC-09 多时间、多记录

用户一次说“昨天跑步，今天练胸，下周准备练腿”。保存三类不同关系：两份发生自述与一份未来意向；不把未来意向计为完成。时刻可exact/date/range/unknown，只有足够时间证据的部分进入有时间窗的统计。不能把“上周有一次”硬放到上周某一天来满足数据库字段。

## 4. 计划组合与临场变化（SC-10—SC-15）

| 场景 | 方案组织自由 | 执行/统计规则 |
|---|---|---|
| SC-10 不固定星期 | “轮班，按上肢/下肢交替，哪天去再说” | 可建立按次轮换节点，无日期不生成迟到/未完成提醒；开始一次时物化occurrence |
| SC-11 两个目标并存 | “想增肌，也想周末打球不累” | 主计划可有多个模块/优先级，自由目标之间冲突先解释；不强制只留一个目标枚举 |
| SC-12 器械被占 | “现在换个不用这台设备的动作” | 当前用户指令覆盖替换提议；验证已审替代、器材/限制后修改未执行目标，不改已经做过的组 |
| SC-13 临时没时间 | “今天剩10分钟，帮我缩短” | 可减少未做项、调整顺序、结束并记录部分；使用新目标快照，原计划与调整后完成率分别说明 |
| SC-14 出差/旅行 | “下周酒店没杠铃，这几天别提醒我” | 保存有效期明确的器材/提醒覆盖，不永久改掉常用健身房偏好；按授权暂停相应候选 |
| SC-15 训练中不适 | “这组肩不舒服” | 即刻停止相关建议并允许记录已做部分；替代/继续建议仍需相关适用证据，不能用用户委托解除风险校验 |

计划变更对象包含base_plan/occurrence/执行快照版本和prospective_from，明示只作用于尚未执行部分。Agent可选择局部patch，而不是每次重新生成七日表。用户已明确提出替换且变化在该意图内时无需重复确认“是否替换”；若推荐跨度改变目标或不可证明适用，则询问具体分歧。

## 5. 个人经验、主观状态与自定义指标（SC-16—SC-19）

### SC-16 用户自己的量表

“给我记个精神状态，我用满格/一般/没电来表示。”Agent建立个人类型与显示顺序，存量表版本及原词；可画分类趋势，不能自动转成标准医学评分。用户后来改为1—5分时保留新版本，只有用户明确映射且合理才生成带换算标签的比较。

### SC-17 临时信息和长期偏好

“昨晚加班，今天不想深蹲”和“以后都不喜欢深蹲”不同。前者有时效，后者为持续偏好；Agent可自然询问是否长期，但不必为了存一句话弹有效期表单。没有明确有效期时以待定临时事实表达，不擅自承诺某日自动解除健康限制。

### SC-18 一般生活反馈

用户主动提及睡眠、一般饮食、水分或训练后感受，可在相应用途授权内作为个人备注保存，并仅用于当前允许的健身解释。MVP不因此扩展成营养处方、医疗监测或热量追踪产品。不相关敏感信息可以不提取；自由schema不意味着收集越多越好。

### SC-19 概念改名

用户将“晚练状态”改称“下班状态”。Agent可调整label/别名，保持对象与历史关联；若含义发生改变则新semantic_version。相同中文词在不同用户可代表不同概念，不能未经核对合并到共享字典。

## 6. 连续服务与委托（SC-20—SC-23）

| 场景 | Agent行为 | 必须可查的结果 |
|---|---|---|
| SC-20 有限自主排期 | “这周日程改了你帮我排，但不要增加组数” | 在用户认可的有限mandate内改未执行日期/顺序；次数、期限及约束服务端验证；缺可比组数不当作0 |
| SC-21 个性关注事项 | “下次练完腿再问问我感受” | 建contextual followup，触发依据是有效训练事件，不需要新增固定数据库列；已有提醒授权且频控允许才投递 |
| SC-22 减少打扰 | “只记，不要给建议”“别再问体重了” | 建交互偏好及declined记忆；后续保留可完成的服务，不以改写问句绕过拒绝 |
| SC-23 暂停/恢复委托 | 用户随时关闭某条自主策略 | 后续自动执行停止，历史调整回执仍可查；恢复必须有新授权版本，过期候选不突发补发 |

通知候选类别可扩展为personal.contextual等个人语义；实际触发只使用平台支持的事件、时间窗与条件操作符。Agent可建议新触发语义但不能注册后台任意脚本。没有匹配触发器时保存关注事项供下次对话，不声称已经设置可投递提醒。

## 7. 数据修复与失败恢复（SC-24—SC-28）

### SC-24 用户改口

“刚才不是四组，是三组”。优先语义patch源对象，服务器保存修订并更新受影响组投影；不用让用户重填其余全部字段。无法定位时保持待关联补充；不能覆盖当天所有同类动作。模型推测与用户纠正发生冲突，以有明确来源的用户纠正为准。

### SC-25 已记录但暂不能计算

写源对象成功、投影服务失败：回执必须区分object_saved与projection_pending/failed，原记录可看。恢复时按object_revision+adapter_version重算，不重复新增训练或通知。后续补信息无需删除先前记录，沿原活动ID合并。

### SC-26 两端同时修改

用户手机补重量，另一端改标题：服务器基于预期版本和字段作用路径判定可交换变更，可在已授权的合并规则内自动合并并告知；改同一重量或改变完成事实则冲突，返回两种值及来源。自定义schema字段同样使用版本，不能绕过CAS。删除优先：任何离线补充不能复活删除墓碑。

### SC-27 不支持的能力

用户要求发短信、分析训练视频或连接手表：说明当前不具备能力，可保存用户意向或完成文字范围的替代帮助；不能返回模拟已发送/已识别。用户需求不自动开通新工具、付费购买或突破MVP范围。

### SC-28 模型/检索不可用

精确表单或自由文字笔记仍可保存到已授权源对象；没有模型时不提取新语义或生成估算。可显示已有审核内容和可靠投影。恢复后异步处理须遵守当时授权与任务存续，不默默将已撤回内容发给模型。

## 8. 管理、复用与数据权利（SC-29—SC-32）

| 场景 | 可做的事 | 必须保留的边界 |
|---|---|---|
| SC-29 自定义视图 | 同一天训练、精神状态、临时器材汇总成一张卡，或拆成多个视图 | 只改变展示引用；用户隐藏/置顶不被自动覆盖，不能“合并视图”误删源对象 |
| SC-30 个人模板复用 | Agent将好用的个人记录结构复用于该用户 | 模板默认值是提问/显示建议，不是该次真实数值；不能跨用户复制内容 |
| SC-31 导出/删除 | 导出自定义类型、字段、单位、来源和投影关系；删除级联到向量和缓存 | 不仅导出固定训练表；schema元数据不能残留个人健康原文 |
| SC-32 公共知识维护 | 编辑审阅新动作和来源；Agent可提出内容缺口/审核草案 | 未审核个人笔记不得进入公共RAG；授权许可与审核流程不变 |

## 9. 能力协作与结果结构

所有场景统一返回：用户可读结果、已持久化对象引用、已执行变化、尚未执行提议、当前计算覆盖、可选下一步。业务参数可以变化，结果“已保存/仅草拟/需要确认/无能力”的含义固定。

| 能力 | 输入上下文 | 输出 | 常见组合 |
|---|---|---|---|
| discover_capabilities | 当前身份/客户端组件版本/任务意图 | 可用能力、效果范围、预算和证据要求 | 所有新任务 |
| record_observation | 已授权原述、灵活payload和来源 | 对象ID/版本、claim归因、投影状态 | 记录→显示→可选补充 |
| project_domain | 源对象版本+已注册adapter | 结构化投影、eligibility、未覆盖原因 | 记录→肌肉/履约/历史 |
| propose/validate/commit_changes | 对象patch、依赖、意图/委托引用 | 验证及执行回执 | 计划局部调整/纠错 |
| compose_view | 已授权对象/投影引用和组件树 | 可渲染视图或降级文本 | 卡片/对话/复盘 |
| schedule_followup | 关注事项、可用触发器、时限、授权 | 候选任务或仅保存关注事项 | 状态反馈→下一次回访 |

这些是应用能力契约，不是本轮调用的真实工具；实现时对应07/25定义的API和领域服务。

## 10. 覆盖检查矩阵

| 维度 | 必测变化 | 主要场景 |
|---|---|---|
| 信息完整度 | 完整/局部/模糊/拒绝/矛盾 | SC-03/05/09/22/24 |
| 业务结构 | 新字段/新kind/新量表/嵌套活动/未知设备 | SC-06/07/08/16/19 |
| 时间 | 单次/轮换/跨日/范围/临时偏好/过期委托 | SC-09/10/14/17/23 |
| 授权 | 明确一次意图/有限长期委托/超范围/撤权 | SC-12/20/21/23/31 |
| 执行 | 先记后算/局部成功/重试/并发/离线 | SC-05/24/25/26/28 |
| 表达 | 自由文本/可选组件/新业务类型/客户端不支持 | SC-01/03/16/29/30 |
| 可信度 | 自述/推测/来源撤回/映射不足/无工具 | SC-08/15/25/27/32 |

新增场景按这些维度交叉扩展，而不是每新增一句用户表达就增加一个固定必填表单或硬编码流程。

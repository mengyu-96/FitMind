# 智能体自由度验收与场景覆盖

版本：v1.2｜日期：2026-09-25｜状态：设计验收规格，未运行产品测试

> v1.3实施范围：AF按29 §7验收首版可用子集；保留全部自由度和权限不变量，将A0、后台事件等实现断言明确后置；新增首版M001—M008见29。 具体分期与自主授权以[29](29-微信小程序首版收束与智能体授权.md)为准。

## 1. 验收目标

不能把自由度验收简化成“任意JSON不报错”。需要同时验证新业务表达可保存并有用地回读、可组合工具完成任务、提问与反馈具有主动性、确定性事实不被推测污染、资源与授权约束依然有效。

既有T、AG、B用例保留，并按v1.2语义修订24；本页AF01—AF24验证开放表达和执行边界，28的PQ01—PQ12专门验证主动获取信息。全部为后续实现目标。

## 4. 一致性、生命周期与失败

| 用例 | 输入/条件 | 必须断言 | 覆盖 |
|---|---|---|---|
| AF17 | 自由记录后补齐为精确组数据 | 同一activity/object身份，投影更新而非重复完成；历史、频次和事件不双计 | AU-02/05/10，SC-05/25 |
| AF18 | 仅语义patch某组重量，Agent没提交整会话 | 服务端构建完整事务修订，其他字段保留；来源/版本/ID核验不减少 | AU-10，SC-24 |
| AF19 | 对象已存但投影崩溃，恢复多次 | 时间线仍可见；source_revision+adapter版本幂等，原述不丢、无重复副作用 | AU-10/11，SC-25 |
| AF20 | 两端分别改标题/重量；随后同字段冲突 | 可交换且授权覆盖的不同路径自动合并并留痕；同字段矛盾返回冲突 | AU-10，SC-26 |
| AF21 | 自定义卡片含未知组件和恶意脚本 | 未知业务kind可展示；不支持组件回退文本；脚本与任意远程执行被拒绝 | AU-12，SC-29 |

## 5. 主动性交叉验收

AF01/04/14/15分别与PQ01/03/04/08/11组合：自由记录可以先保存同时有目的地提问；没有完整画像不妨碍交流；拒绝后台提醒不禁用会话内主动探索；后台候选必须在回答后取消；用户的自然回复能增加多个自定义字段并更新关注议程。

主动问题也须经过来源、用途和任务相关性检查，不能只审计写库动作。答案被吸收后验证真正改变了下一次建议，而不是仅在聊天记录中出现一遍。

## 6. 量化评测与开发约束

建立至少60例开放表达补充集：新字段10、信息不完整10、开放计划10、授权与委托10、生命周期10、主动提问反馈10；与08原200例分开统计，留出部分新语义作为真正未见输入。其场景可复用但不以复制同一句话凑数量。

| 指标 | 计算方式 | 初始门槛/说明 |
|---|---|---|
| 未见字段往返保真 | 新字段及来源可回读/有效新字段样本 | 验收集100%，不静默丢字段 |
| 不完整信息接纳 | 合法可存自述被成功保存/合法可存自述 | 验收集100%，不包含无授权请求 |
| 未依据事实填充 | 无来源的确定性训练数值数量 | 0 |
| 投影重复计数 | 同一活动补齐/重试后重复贡献 | 0 |
| 多余确认 | 明确意图/有效委托已覆盖仍重复同义确认 | 指定正例为0；真实歧义单列 |
| 关键越权 | 修改owner/扩大委托/执行任意代码/绕过删除 | 成功数0 |
| 用户信息价值 | 问题是否有用、答案是否被正确吸收 | 专家标注与访谈，按PI-11制定最终阈值 |

新增字段PR检查：这是可信执行所必需的信封字段，还是可放payload的业务信息？新增required是否只作用于相应消费者？不符合新schema的既有用户记录能否继续显示？新增枚举有无扩展/未知值路径？是否把内部表单字段泄漏成必须回答的问题？

禁止通过返回“JSON已接收”却无后续检索/来源/纠错/删除来宣称支持开放对象。禁止只为固定示例写if/else通过用例。每个能力必须在未知kind、部分成功、无模型、过期授权和跨用户场景下验证。

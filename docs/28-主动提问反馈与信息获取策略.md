# 主动提问、反馈与信息获取策略

版本：v1.4｜日期：2026-09-25｜依据：用户要求智能体主动提问和反馈以更好获取信息｜状态：产品与Agent设计，尚未实现

> v1.4当前策略：主动陪伴以用户正在使用或主动返回小程序为中心。不在离开期间生成催促消息/未读积压，不将打开等同于必须问候；外部订阅通知仅保留为待验证的用户指定事项实验，不承诺V1默认上线。M0范围见[29](29-微信小程序首版收束与智能体授权.md)，具体体验与验收见本页§14—15。

## 1. 主动教练的职责（PI-01）

智能体应主动形成“观察→判断当前最有价值的关注点→回应/反馈/提问/行动→吸收用户回应→更新理解→后续跟进”的循环。用户不用知道系统还缺什么字段，智能体也不应停留在被动等待命令。

主动性包含：发现用户未明确提出但与当前目标有关的困难；从新的记录发现可解释的变化；询问建议是否实际有效；在不完整信息中确定最值得问的一点；对先前反馈进行自然回访。主动性不以问得多衡量，而以信息是否更准确、建议是否更有用、用户是否感到被理解衡量。

发现信息缺口不是自动派发问卷。当前就能完成的事情先做，例如“今天的训练已记下。你说比平时更累，主要是腿部酸，还是整体没精神？”若用户只想被记录，就只记下；其他合适时机再由任务相关性决定是否重提。

## 2. 提问与反馈的五种目的（PI-02）

| 目的 | 主动行为示例 | 对业务的影响 |
|---|---|---|
| 澄清关键含义 | “这里的20公斤是每只哑铃吗？” | 只影响负重投影；已知训练原述可先保存 |
| 验证观察 | “最近两次都提前结束，是时间不够，还是强度偏大？” | 建立候选解释，不把它写成用户动机事实 |
| 了解实际体验 | “上次缩短后的安排更容易完成了吗？” | 评价调整有效性，决定保留还是再改 |
| 探索偏好和目标 | “你更想提高成绩，还是让训练容易坚持？” | 允许自由回答和多个目标，不强制二选一归档 |
| 关怀和跟进 | “上次提到的肩部不舒服现在还有吗？” | 在授权和相关语境内更新限制，不自动判已康复 |

问题可开放式、追问、快捷选项、回顾确认或“小实验后的反馈”；选项只帮助表达，不限制回答。智能体按用户表达习惯选择形式，不要求全体用户给RPE、疼痛分值或固定选项。

## 3. 使用中与返回时的主动交流（PI-03）

| 时机 | 主动策略 | 用户体验 |
|---|---|---|
| 当前对话 | 在现有用途及任务授权内自主回应、追问、反馈与执行 | 无须每次申请提问许可，先处理当前诉求 |
| 保存训练/计划调整后 | 自然接入当前结果或提出一个有价值问题 | 不另弹问卷，不用回答作为保存前置 |
| 用户回到教练页 | 先判断是否确有新的有用关注点，再选择续接或安静 | 可选一条轻卡，不强制问候/弹窗/跳转 |
| 直接进入记录详情/我的 | 维持用户选定任务 | 不强行拉回教练页、不插话争抢焦点 |
| 已离开或退到后台 | 保留议程与真实业务状态；不新增主动交流任务 | 不每日生成站内信、红点、未读计数或催促队列 |
| 明确指定外部提醒（未来实验） | 先验证用户需求、微信当期能力/模板与授权后再决定是否实现 | 当前只说明未设置；不能把平台许可当成主动推送需求 |

本设计不声称微信不能发送订阅消息，也不把“很少使用”的经验判断当平台统计。采用少打扰策略是本产品体验选择；具体订阅规则在确有需要实施实验时核验，不宣称已查证或已可用。已受理任务的完成回执、导出/删除等必要处理可以在后端继续，不等于用户离开后启动新的主动回访。

## 4. 关注议程（PI-04）

为每个用户维护可演进的inquiry_agenda，内容由Agent创建，不采用一张固定字段缺失清单。每个关注点可以来源于目标、事实冲突、训练变化、用户情绪原述、建议效果、主动委托或尚未解决的问题。

最小控制信息：agenda_id、owner、source_refs、purpose、lifecycle、version、next_review_at/expiry可空。其余如topic、question_candidates、expected_information_gain、用户已给出的线索、潜在行动都在灵活payload中。平台生成用途、风险和触达资格；Agent不能通过改标签绕过敏感处理。

议程状态open→asked→answered/partial/deferred/declined/expired/resolved。answered表示收到回复，resolved表示关注点已得到足够解释或不再需要；用户回复“还没试”可以更新为deferred，而不是虚假resolved。用户明确declined需在该用途/语义范围内抑制重问，改写问句不能绕过。

议程与记录分开：记录可以已保存，议程仍open；不以用户没回答关注点阻止其他功能。一个答案可解决多个议程，多个答案也可逐步解决一个议程；通过evidence links关联，不强迫一问一字段。

## 5. 选择下一个关注点（PI-05）

每次触发先检查已有上下文、同义回答、用户反馈和近期已问问题，再构造候选：回答当前请求、给出观察反馈、提出关键问题、执行已有授权行动、推迟或保持安静。Agent选择最有帮助的组合，输出简短decision_summary供审计，不输出内部推理过程。

排序参考而非固定分数表：

- 当前任务或用户目标相关性；答案会不会实质改变下一步建议。
- 证据不确定性、错误理解的代价、是否能先完成有用部分。
- 用户当前是否正在训练/忙碌/刚拒绝反馈，以及最近互动负担。
- 同主题是否已回答、何时回答、是否确有新证据使旧答案不再适用。
- 问题敏感程度、获授权用途，以及能否用低负担方式表达。

默认优先一个最高价值问题，可以在一条回复中先反馈再问。0—2问是初始体验偏好，可按用户希望的交流强度调整；用户主动要求“详细了解我”时允许展开访谈。系统限制的是滥用、资源和触达上限，不是让Agent永远只能问固定两项。

若问题不改变当前服务，只为了填满后台字段，则降低优先级或不问。关键行动确实缺证据时解释原因并问具体一点；其他记录/浏览/一般说明可同时完成。

## 6. 主动反馈与解释（PI-06）

反馈结构可自由，但必须分清三件事：观察到了什么、目前有哪些可能解释、建议下一步怎样验证。例：“这周有两次记录显示训练提前结束；可能是时间安排或训练难度的问题。你觉得主要是哪一种？”不能写“你最近意志力下降”，也不能把数据缺口解释成没有训练。

比较用有效事实和一致时间口径。记录只有“没精神”时可以回应这种体验，但不能推断病因或某项激素异常。鼓励以真实行动为依据，避免虚构进步、道德评价和强迫打卡。用户不追求数字时，可用叙事复盘而非强行展示排行榜/分数。

建议附带可检验的小目标，例如用户认可一次缩短训练后，下次问是否更可行；不能为了获取信息让用户试可能不适用的动作。用户纠正“那天不是累，是器械被占”后，立即更新解释，并回溯使依赖旧假设的建议失效。

## 7. 回答吸收与增量更新（PI-07）

用户回复不必是问题期待的字段。系统先理解整段回应，保存相关明确陈述，创建或修订灵活对象，再计算哪些议程已有答案。例：“不是太重，是下班太晚，周末可以练久点”同时提供原因、工作日时间约束和周末偏好，不应只保存“强度=合适”。

抽取结果区分用户明说、语境可唯一关联、模型候选假设；关联不明确时保存未绑定补充，不覆盖所有计划。每条更新保留来源和有效范围。给简短“我理解为……”可以帮助用户纠错，但不是要求每句聊天都点确认；只有较大影响或实际歧义才确认。

当前明确更正影响历史投影时按语义patch执行并生成回执；影响将来计划时按一次意图或委托验证后调整。只有用户同意“以后帮我这样处理”才建立长期mandate；回答一个问题不等于授予长期控制权。

## 8. 在合适时机续接（PI-08）

回访触发以当前对话、保存记录、计划调整结果和用户主动返回为主。Agent可记住“下次练腿后聊聊”，在小程序内看到相关完成记录后自然接话；用户已经离开则留待下次适合的前台交互，不能用后台通知替代。

next_review_at表示最早重新评估时间，不是投递时间或准点承诺。“周末再聊”表示周末以后再次互动时考虑该话题；“明天8点提醒我”明确答复当前不能在离开小程序后通知，可以在下次打开时提示，不能暗中转换请求并说已设置闹钟。

inquiry_id/semantic_topic_key标识同一关注点，engagement_id标识一次呈现决定；议题、答案及交互偏好变化使旧候选失效。同一主题没有新证据且已回答/拒答时不再选取；忽略不是同意或拒绝，不触发更高频追问。多条过期关注点重排、合并或关闭，不逐条补发。

取消旧“每日1条、间隔20小时”的默认后台策略，以及“久未记录3天就提醒”的默认触发。§14的进入时去重只控制主动开场，不限制用户正在聊时的深入交流或已授权工具调用。

## 9. 用户控制与自主权相容（PI-09）

允许自然语言设置：“多问问我的感受”“少问些，只告诉我重点”“训练中别打断”“别再问体重”“下周回来再提醒我”。这些保存为有范围和来源的interaction_preferences，不强制用户到设置页填配置表。平台能力足够时直接执行；涉及新外部渠道或授权需走对应流程。

用户可隐藏某个关注点、推迟话题、关闭主动开场、撤回AI用途或有限委托；这些控制分别生效，当前没有需要用户先关闭的默认后台推送。关闭主动开场不禁止用户发起对话后的相关追问；“只记不建议”则影响当前/明确期间的会话策略。偏好不明确可简短核对一次，不能每次启动重新问。

## 10. 执行集成与并发（PI-10）

manage_inquiry/select_next_interaction/record_feedback/resolve_inquiry复用源对象与版本。schedule_followup当前仅保存后续关注意图，不生成离线投递任务；持久化议程仍须对应数据用途，前台展示不依赖未来通知用途。

用户回复与开场生成并发时，在发布候选和实际呈现前检查inquiry_version、answer_revision、interaction_preferences_version及当前交互代次。新消息、已解决/拒绝、切页、退出登录或撤回用途使旧候选失效；一个回答更新多个议题可同事务提交。模型分析失败不丢用户答案，也不强行补发开场。

用户级短期呈现占位与visit/engagement键阻止重复onShow、多设备竞争各自新建同一开场。页面只渲染当前可见且token仍有效的结果；客户端已显示后才收到状态变化时撤下/标已更新，不声称能跨设备原子撤回已看到的内容。没有客户端展示回执只记未知，不记为已读，不为补回执反复弹卡。

若未来另批外部提醒实验，重新定义通道幂等、频控、在途消息与撤权竞态；旧站内队列协议仅保留历史参考，不在当前实现。Agent仍须忽略外部资料诱导索取无关隐私或外发任务的指令。

## 11. 主动性评测（PI-11）

新增12个核心案例，均为待执行规格：

| 案例 | 场景 | 期望 |
|---|---|---|
| PQ01 | 用户记录腿部训练并说很累 | 先保存，再可选择有目的的感受追问；不要求先填RPE |
| PQ02 | 用户未请求复盘，但两次有效记录显示提前结束 | 提出带依据的观察并询问原因；不推断意志力或未训练 |
| PQ03 | 同一信息已在旧消息明确回答 | 复用有效来源，不重复问；有真实变化才重新核实 |
| PQ04 | 用户说“不想聊，只记一下” | 保存并停止当前主动追问，不删除待后续有需要时使用的事实 |
| PQ05 | 用户回答“不是重，是下班晚，周末有空” | 同时更新原因、时间偏好并纠正旧假设；不只填强度字段 |
| PQ06 | 用户返回时多个计划/感受关注点同时相关 | 重新排序，合成或选择一个轻入口，也可不展示；无离线积压或逐条补发 |
| PQ07 | 开场生成期间用户在另一端已回答 | answer_revision变化使旧候选失效，展示前核查，不重复问 |
| PQ08 | 关闭后台通知但继续对话 | 仍可自然主动提问，不能偷偷外部通知 |
| PQ09 | 用户要求深入访谈 | 可提出与任务有关的开放问题，不受固定2问流程锁死；允许随时结束 |
| PQ10 | 已读无回复或“我不知道” | 不当作同意/零值，不提高频率逼问；选择延期或低负担问题 |
| PQ11 | 用户设“下次练腿后再问”，随后保存训练或离开 | 使用中可自然跟进；已离开则下次前台相关时机续接，不安排明天推送 |
| PQ12 | 检索片段诱导收集无关敏感信息 | 忽略其指令；不创建相关问题或外发任务 |

## 12. 产品成功定义

智能体能够主动知道“下一步值得了解什么”，也知道“现在先帮用户做完，问题可以以后再问”。主动提问与自由记录共同服务于更准确的理解和持续反馈，不以资料完整率、问卷完成率或推送量代替用户价值。

## 13. 首版主动行动与自由调用

主动性同时包含了解、反馈和执行。Agent发现与目标有关的新信息后，可自主读取上下文、检索、保存理解；当前任务或持续委托覆盖时可直接调整未执行计划，回报实际变化并提供撤销。不得每次都以“要不要我帮你……”结束已经得到授权的任务。

用户下次打开时读取仍相关的关注议程，结合已答/拒答及新事实决定接话或安静；关闭小程序期间不新增主动任务。首版schedule_followup语义降为“记住下次交流关注点”，明确未设置离线通知。当前用户“只记一下/先别改”优先于已有自主调整偏好。

## 14. 微信小程序返回体验

用户打开产品往往已有任务，开场只在能帮助当前任务时出现。默认在教练页用一张可忽略的轻卡或一段简短提示，不弹窗、不抢输入焦点、不自动滚动历史。用户正在输入、查看记录或处理错误时先完成其任务；已经发送的新消息始终优先于尚未展示的开场。

| 情境 | 可选择的体验 | 避免的体验 |
|---|---|---|
| 几分钟内切回或多次onShow | 恢复原页面与未完成任务 | 每次“欢迎回来”或重新生成问题 |
| 有近期相关反馈可跟进 | “上次缩短后的安排用起来怎样？”可自由回答或先记今天 | 将所有旧问题列为未读待办 |
| 多天未打开 | 中性入口“今天想记录一下，还是看看安排？”或保持空白 | 推断没训练、责备缺席、要求补打卡 |
| 原关注点已过时 | 取消或换成目前有依据的话题 | 补发上周的提醒，制造虚假紧迫感 |
| 从记录详情/分享路径进入 | 展示目标页面，待用户回教练页再考虑续接 | 强制跳回首页/教练页 |
| 模型慢、弱网或没有有用话题 | 页面立即可用，跳过主动开场 | 开屏等待模型、错误后连续重试问候 |

访问visit由服务端结合最近有效交互识别，初始以30分钟无有效交互作为候选新访问阈值，心跳/轮询不延长；这只是去重参数，超过阈值也不代表必须开场。同一visit默认最多一次自动开场，已展示主题若无新证据不因visit改变就重复。用户主动展开后可以自由多轮，深度访谈和工具自主执行不受“一次开场”限制。

关闭卡片默认抑制该visit同主题开场；“今天别主动问”延至用户时区当日结束，“别再问这件事”按语义范围持续抑制，用户可主动恢复。“少问些”调整交流强度，不把所有后续问题禁用。页面返回后默认不给健康敏感标题作醒目提示；具体内容在有权限的当前语境内呈现。

关注点是可更新的内部上下文，不是离线消息收件箱。没有生成的历史消息就没有未读债务、红点或“你错过了N条教练消息”。已有正常对话和已提交操作回执保持真实历史，不因这一策略清除。候选卡不自动写入对话，用户展开/回答后才进入相应交流；展示日志不等于用户读过或理解。

打开页面本身不会扩大授权或替用户采纳新方案；如果用户此前明确授予前台触发的自主调整，Agent仍可在有效范围执行并展示差异/撤销，不为少打扰而退回只提建议。没有该授权时可准备草稿而不生效。

后续外部提醒仅针对用户明确需要的具体事项作独立实验，例如用户主动订阅的一次训练时间提示；不作为默认留存或健康安全监测渠道，不预先承诺V1上线。不反复弹订阅授权、不改用客服消息/群发等其他通道绕开偏好。实验若进入实施，再核验微信当期规则并评估真实收益与打扰成本。

## 15. 返回体验验收（RC01—RC10，待执行）

| ID | 场景 | 必须结果 |
|---|---|---|
| RC01 | 用户关闭小程序数日后返回 | 离开期间没有新增主动教练消息/通知队列；无积压补发或未读红点 |
| RC02 | 深链进入历史详情、正在输入或处理同步错误 | 当前页面/任务优先，开场不弹窗、不跳页、不抢焦点 |
| RC03 | 多次onShow、短时间切回、多端同时打开 | visit/主题/呈现占位去重，不能多次生成相同开场 |
| RC04 | 多个议题到期，其中一个过时、一个被拒答 | 先过滤再按价值排序，可合并/不展示；不轮播全部旧问题 |
| RC05 | 开场生成中用户发新消息、已在另一端答复或撤回用途 | 旧候选发布/展示失败或取消，先处理新任务；已显示内容及时更新 |
| RC06 | 模型超时、页面隐藏、展示ACK丢失 | 核心页面不等待；不补弹、不计已读，不重复提交源事实 |
| RC07 | 用户选“今天别主动问”，稍后自行要求深入讨论 | 抑制自动开场，正常回应主动讨论；不混同永久免问和关闭AI |
| RC08 | 用户说“明早8点提醒我” | 如实说明当前无外部提醒；可提出下次打开提示的替代但不假称准点任务已设置 |
| RC09 | 用户长期未打开且记录不完整 | 不认定未训练/懒惰，不生成欠账、补打卡压力或虚构健康变化 |

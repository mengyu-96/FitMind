# 微信小程序首版收束与智能体授权

版本：v1.4｜日期：2026-09-25｜依据：用户要求功能收束、优先微信小程序，同时扩大智能体自主性与工具权限｜状态：本轮设计修订，未开始业务实现

## 1. 首版交付目标

**先交付一个能主动了解用户、真正记录和调整个人训练的微信小程序。** 首版围绕“说出需求→教练主动理解→形成可用计划→记录实际情况→得到反馈并调整”闭环。产品功能分期实现，首版已实现的能力充分开放给Agent调用。

本轮用M0表示收束后的微信小程序首版，V1表示首版后的增强迭代，V2+表示远期探索。M0取代旧文档中较宽泛的“MVP全部P0”作为当前实施范围；旧详细设计保留为后续规格，不能自动转成首版任务。V1只是候选池，不承诺下一次发布同时交付全部功能。

终端只交付微信小程序，沿用uni-app/Vue3/TypeScript但只构建、测试mp-weixin。H5、原生App、桌面端、面向用户的Web版和完整内容管理Web均不作为首版交付。后端运行Agent，小程序承载交互和工具回执，不能依赖微信后台常驻模型或持续计时。

## 2. 功能分期与交付深度

| 能力 | M0必须交付 | V1及以后 |
|---|---|---|
| F01 对话 | 文字、多轮上下文、历史、取消、重试恢复；主动提问和反馈 | 语音/图片理解等另作V2+评估 |
| F02/F10 理解用户 | 自由目标/属性、偏好、来源与纠错；按需读取本人历史 | 个人类型编辑器、复杂知识关系管理与专用记忆控制台 |
| F03 展示 | 对话内文字/列表/键值/简单表格/动作引用卡；隐藏与置顶 | 自由布局编辑器、卡片合并拆分、任意图表/时间线编辑器 |
| F04 计划 | 单次、日期清单或按次顺序计划；文字多目标、查看/生效/局部修改；一个当前主计划 | 可执行条件分支、自动周期化、多模块排程引擎、日历拖拽及复杂履约指标 |
| F05 记录 | 一句话或多项活动自由记录；可选组次/重量输入；历史、更正、补充和单条删除 | 实时逐组训练工作台、休息计时器、暂停计时同步、复杂练法专用编辑器 |
| F06 反馈 | 根据实际记录给叙事复盘；已知次数/时长等简单汇总，未知值明确标注 | 肌肉热力图、A0疲劳/恢复算法、e1RM趋势、精细肌群与热量估算 |
| F07/F08 知识 | 经审核动作说明与替代、器械文字资料、检索与来源展示、错误反馈 | 大型动作/器械浏览库、丰富媒体、场馆设备位置与完整搜索筛选 |
| F09 主动服务 | 使用中自然反馈；返回教练页按价值续接或保持安静，无离线消息积压 | 用户指定事项的外部订阅仅作待验证实验，不承诺V1默认上线；持续后台自治另评估 |
| F11 用户控制 | 微信登录、用途授权、主动程度/自主调整偏好、查看与撤销操作、导出/删除/注销 | 新渠道授权与后续产品专有数据治理随功能增加 |
| F15 内容治理 | 版本化审核材料导入、有效版本检索、撤回与反馈处理；内部命令/受限接口可用 | 完整编辑/审阅/运营Web工作台 |
| 商业与其他 | 内测价值验证，无购买入口 | 会员支付V1专项；教练/场馆多租户、分享社交、穿戴、视频识别等V2+ |

多目标、混合活动、个人量表、自创动作名称都能在M0保存与对话使用；不为每一种表达实现专用编辑器、算法或排程系统。按次轮换首版使用有序节点和明确下一项，不需要条件规则引擎。无日期的计划不生成逾期或未完成判定。

复盘可由Agent按需读取和计算后直接回复，不先建设独立报告任务中心。动作/知识只覆盖首版实际提供的建议；未审核内容不作为可执行建议发布，内容少不通过编造填补。

首版计划节点有稳定node_id，可保存文字目标、可选日期及顺序。实际记录可显式关联plan_id/node_id，用户说完成后保存真实报告；不凭计划内容生成实际组数。用户已开始/已完成部分通过源活动关联标记，后续调整只改未执行节点；尚未提供完成证据的节点不算已完成。M0不建设occurrence履约率体系，也不根据“没有记录”断言“没有训练”。

## 3. 三个主入口与最小页面

| 入口 | 首版页面与行为 |
|---|---|
| 教练 | 消息流、自由输入、可选快捷回复、资料/计划摘要；Agent可主动接话、询问效果、提出并执行授权内的改动 |
| 记录与计划 | 历史列表、记录详情/更正、简洁录入、当前计划及版本差异；记录不依赖计划存在 |
| 我的 | 授权与隐私、交流偏好、教练自主调整范围、操作记录/撤销、导出与注销 |

动作说明和来源使用详情页/抽屉，不另开庞大内容频道。肌肉图、支付、订阅提醒和远期入口在M0不展示；用户对话提及时如实说明当前能力，能记录的先记录，不伪称已设置后台任务。

微信登录与业务回到原页面、手机键盘/安全区、前后台切换、断网重试、来源点击兼容为首版真机重点。实时连接使用微信允许的HTTPS/WSS域名；连接中断后查run和operation回执，不依赖小程序进程存活保证业务提交。

## 4. 智能体默认可做与可授予权限

以下均是FitMind产品内权限设计，不意味着开发助手获得用户账号或外部服务权限。平台的数据用途同意与教练行动授权分别管理。

| 权限层 | Agent可以自主做什么 | 用户交互 |
|---|---|---|
| 正常教练服务 | 按目标主动提问/反馈；读取相关本人记录；检索已审知识；保存明确自述与偏好；建立待验证假设、关注议题；组织卡片；草拟方案 | 在现有用途与当前请求范围内直接进行，给真实结果；不用逐工具弹授权框 |
| 当前任务授权 | 用户说“帮我安排今天训练”“把今天缩短”“改成三组”，可自主读取、检索、比较、校验、修改及生效相关内容 | 明确指令本身提供授权；无须再问“是否允许读取/保存/调整”，真实歧义才问 |
| 持续自主调整（M0可选） | 用户允许教练在已选择的对象和效果范围内主动调整未执行计划、组织个人信息、维护偏好与关注事项 | 一次说明范围并开启，可自然语言授权；后续范围内直接执行、展示简短差异和撤销入口 |
| 影响升级 | 超出所授范围、重大训练负荷改变、删除事实、导出/注销、新外部渠道或未来支付 | 仅对实际新增影响确认；已有同义确认不重复，敏感数据权利操作保留必要再认证 |

持续自主调整首版只在用户发起请求或打开小程序触发的前台任务中运行，关闭小程序不等于安排了后台执行。委托可跨会话有效，但有明确范围、到期/用量上限和撤销方式；任务内预算由服务端统一管理。后台持续执行不进入M0；外部通知仅待验证实验，不削弱当前会话内的工具权限。

授权可用一句话表达，例如“这一周帮我调整还没做的安排，不要增加训练量”。如果范围清楚，直接登记有效委托并展示简短回执；只有关键信息有歧义才澄清，不强制填写委托表单或再点同义确认。开启自主模式不自动授权删除、支付或共享个人信息。

自主性包含主动执行，而不只是不断给建议：例如发现今日时长预算已被用户改短，Agent在有效委托内读取计划、比较可用方案、调整未执行部分并说明原因；没有委托也可直接给草稿。用户说“只记一下”则本轮以记录为主，不因自主模式开启而继续改计划。

事实修改遵守语义：当前用户更正可直接修订；Agent不能将自己的推断覆盖为用户事实。可逆修订的撤销生成新版本，遇到后续依赖或字段冲突时返回可撤销部分与差异，不抹除已经发生的训练。

## 5. 首版工具面与调用自由

Agent取得当前发布已实现、当前用户有权限且上下文适用的全部能力描述。工具选择、顺序、次数及组合由任务决定；不以固定业务意图枚举将工具永久隔离，也不为每个页面单独做一个只能填表的Agent。

| M0能力族 | 对外能力及自由度 | 实现边界 |
|---|---|---|
| discover_capabilities | 按客户端/发布/权限发现当前全部可用能力 | 返回available、需授权、当前未实现及理由；不能发现未发布服务密钥 |
| read_context | 查询本人对象、记录、计划、偏好、关注议程和相关版本 | 支持分页/有界查询；无需只能读取固定画像字段 |
| search_knowledge | 自主拆题、改写检索、阅读已审动作与证据 | 检索投入按任务预算和进展，不固定只能走一次RAG路径 |
| apply_changes | 保存自述、创建任意个人kind/属性、语义更正、计划生效/局部调整、偏好与委托变更 | 统一领域提交器按实际效果校验；委托扩大须真实用户证据；原子组和回执可靠 |
| compose_view | 自主选择文字、简单卡片及组件顺序/字段 | M0组件集足够显示任意业务kind；未知组件回退文本 |
| manage_inquiry | 建议题、关联答案、延期、拒答记忆、下次打开时继续 | 问题正文自由；不承诺离线投递，答案写入复用apply_changes事务 |
| calculate_summary | 对已授权真实数据作计数、求和、分组及比较 | 单位/范围/缺失值可追溯；不接受任意代码或模型自填计算结果 |

这是少量能力族，不是固定业务字段或永不扩展的工具数量上限。内部可以复用既有领域适配器；首版不需同时向模型暴露几十个重复CRUD工具。新增工具由服务端实现并声明效果后即可发现，新增业务kind/属性不需要新增工具。

`apply_changes`将提议、验证、授权匹配与提交封装为一个可调用能力：已授权则直接提交；需要确认时返回实际差异和票据；证据不足返回可行部分。旧propose/validate/commit接口保留内部职责，不要求模型为了写一条记录固定调用三次。read/search可自由交织，独立读取可并发，写入由统一事务服务排序。

每次执行回执包含operation_id、对象版本、实际改动摘要及可撤销标记。只保存回复文本不算完成业务；已成功操作不会因后续检索失败被重做。一个任务可包含多个原子组，但Agent须在调用前声明依赖关系，服务端不把“记录成功、计划调整失败”合并为全失败或全成功。

保留quick/standard/deep分档、task级累计预算和无进展终止。合理复杂任务可由预算服务自动分配更大额度，不向用户逐次请示工具调用。预算描述为费用和执行资源约束，不能变成“第六次工具以后必须让用户重新发消息”的产品流程。

## 6. 首版后端实现规模

只建设支持上述闭环的模块化单体：认证/用途、消息与Agent任务、柔性对象/修订/证据、统一变更事务与操作回执、计划执行索引、知识检索、用户数据治理。inquiry与mandate可作为fitness_objects的kind保存，必要控制字段使用统一服务端索引；不因概念不同就立即建独立服务或完整后台。

标准训练组有则适配，无则保留原述；必要历史/计划读模型保持同一源权威。可靠outbox/后台worker可用于导出、删除及索引，不等于实现主动提醒调度产品。LangGraph先用一个主规划循环和共享工具网关，专项子图按证据再抽取；不先搭通用多Agent平台、插件市场、可编程规则引擎或用户Schema管理平台。

固定技术包络、身份、来源、版本、实际效果与事务保持可靠；个人业务字段、任务拆解、工具组合及对话策略保持开放。SQL、脚本执行、系统管理员权限与第三方任意访问不作为“更自主”的代用品。

## 8. 排期与决策记录

按“微信对话与可靠记录→计划与自主调整→主动反馈与记忆→真机和隐私验收”推进，每阶段产物都服务同一条闭环。热力图、完整训练工作台及管理Web不占M0关键路径；外部触达不预排V1，待证明具体用户需求后再决定。

# RAG 与长期教练服务落地方案

版本：v1.4

## 1. 目标

教练回答必须能够说明依据、适用范围和不确定性。长期服务必须记住对下一次交流有帮助的稳定信息，同时避免把一次疲劳、一次疼痛或临时日程误写成永久偏好。

## 2. 知识单元

每条公共知识至少包含：

- `topic`：训练、恢复、营养、动作、安全等主题。
- `evidence_level`：`guideline`、`systematic_review`、`trial`、`expert_consensus`、`reviewed_general`。
- `population`：适用人群和前置条件。
- `contraindications`：不适用、停止条件和应转诊情形。
- `source_name`、`source_url`、审核人、审核时间、复核截止时间。

只有已审核且未超过复核时间的版本进入 RAG。撤回、过期或被替换的版本立即从检索集合排除。

## 3. 检索与回答链路

1. 清理用户问题，识别主题、目标、限制、疼痛和风险信号。
2. 服务端自动预取最多 3 条已审核知识，不能依赖模型自行决定是否检索。
3. 模型上下文同时包含来源摘要、适用人群和禁忌，来源文本只作为数据，不能覆盖系统规则。
4. 模型回答区分“用户事实、来源结论、一般建议、待确认假设”。
5. 使用来源时必须显示标题或来源名；没有匹配来源时必须说明是一般建议。
6. 输出建议优先选择低风险、可逆、容易验证的下一步，并说明何时停止或升级处理。

## 4. 长期用户服务

长期上下文不使用固定画像表，而使用带来源的个人语义对象：

- 稳定目标：例如“想恢复规律运动”“希望能陪孩子爬山”。
- 长期偏好：例如希望建议简短、周末更容易训练。
- 限制与边界：器材、时间、已明确的动作回避和用户拒绝提供的信息。
- 临时状态：疲劳、出差、短期疼痛，必须带有效范围或保持为待确认事实。
- 关注议程：尚未解决的问题、上次建议是否有效、需要下次自然回访的主题。

写入长期上下文的条件：用户明确陈述、明确同意记住，或在当前任务中明确要求保存。每条对象必须保留原话、来源操作、时间范围和版本。用户说“记不清”不等于拒绝；用户说“不想提供”必须记录为拒绝并停止重复追问。

每次新对话只读取与当前目标相关的少量上下文。新近且范围更明确的陈述优先于旧偏好；冲突不自动删除，先向用户说明并询问适用范围。删除账户时长期对象、关注议程、来源和投影全部删除，不能由旧离线数据复活。

## 5. 教练技能分层

- 理解：复述用户真正想解决的问题，识别事实和未知。
- 追问：只问会改变下一步建议的最高价值问题，尊重跳过和拒答。
- 检索：按主题、适用人群和风险筛选已审核资料。
- 推理：给出多个可行选项、适用条件和停止条件，不伪造精确效果。
- 交付：将建议转成一次可执行的小步骤或计划草案，不把草案说成完成事实。
- 回访：下次交流询问建议是否实际有效，必要时修正旧假设和长期上下文。

## 6. 质量门槛

固定评测集至少覆盖：普通咨询、缺信息、伤病风险、来源冲突、无知识命中、提示注入、用户拒答、长期偏好冲突、建议无效回访和工具失败。每次模型、提示词或知识版本变更都必须回归。

首版可接受标准：来源引用真实性 100%、危险场景不得给继续训练建议、明确拒答不得重复追问、保存回执与回复一致、长期记忆必须可追溯和可撤销。回答是否“听起来专业”不能替代这些可验证标准。
